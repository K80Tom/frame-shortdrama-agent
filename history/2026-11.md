## 归档检索约定

- 先搜索本目录的月份/主题文件，再阅读命中的完整小节；不要仅凭标题推断当前实现。
- 每条记录至少包含日期、适用分支/提交（如适用）、问题、采取的做法、验证边界和权威链接。
- 命令输出只保留关键结论与脱敏证据；凭据、私有 URL、个人路径和供应商原始响应不入档。
- 无复用价值的安装、拉取、普通进度刷新不写入历史。

## 2026-11-11：建立统一项目记录入口

**背景**：仓库已有 AGENTS、README、功能台账、文档有效性目录和多份专题进度，但接续开发时需要在多个文件之间自行定位；根目录没有统一的 NOW/MAP/RUNBOOK/DECISIONS/RISKS 记录体系。

**处理**：新增 [PROJECT_INDEX.md](../PROJECT_INDEX.md) 作为 2–4 KB 路由入口，分别建立当前状态、路径映射、操作手册、设计决定、风险触发器与本历史目录。详细能力和测试证据继续链接现有权威文档；随后将记录体系明确为“团队共享主文件＋个人本地补充”，共享 NOW/MAP 只保留项目事实，个人 Git 状态与实际 worktree 移入被忽略的 `NOW.local.md`、`MAP.local.md`，并提供可共享模板。

**盘点结论**：当前产品为 v0.2.0 / Stage 1 单受信 workspace 试运行，目标环境验收仍有缺口。共享文档不保存个人分支差异、工作区路径或本地排期，避免多成员高频更新造成冲突；这些状态由 Git、Issue/PR 和个人本地文件分别承担。

**验证边界**：本次只读检查现有文档、package scripts、Git 状态和 worktree，随后进行文档静态校验；未运行产品构建、测试、数据库、真实模型、部署或付费操作，不形成新的能力验收结论。

**后续维护**：项目状态发生实际变化时更新 NOW；能力证据更新功能台账；长期设计变更追加 DECISIONS；高风险触发条件进入 RISKS；本文件只保留可复用过程。

## 2026-11-11：将记录规则接入 PR 与只读 CI

**背景**：仅依靠文档约定无法阻止成员误提交个人 local 文件、把个人 Git 状态写进共享 NOW/MAP，或遗漏记录更新；需要让同一套规则在本地和 CI 重复执行。

**实现**：新增 `deploy/check-project-records.mjs` 和根命令 `npm run docs:check`，检查必需入口、历史目录、忽略规则、被跟踪的 local 文件、共享 NOW/MAP 的个人状态、本地链接、行尾空白与索引大小。PR 模板新增“项目记录与本地文件”必填检查项；[CI](../.github/workflows/ci.yml) 新增 `Project records` 只读 job，复用同一命令并按 PR base 执行 `git diff --check`。触发路径补充 `history/**` 和 `.gitignore`，未新增写权限、自动合并或发布行为。

**验证**：在 `dev` 基线 `df976eb` 的独立 worktree 中，`npm run docs:check` 通过 12 份受管文档、148 个本地链接；项目记录与工作流治理定向测试 27/27；Actions 只读扫描覆盖 2 个工作流并通过，两个 YAML 均用仓库现有 `yaml` 依赖解析通过；根 `npm test` 完成全包构建，Agent 44/44、Main 1021 通过/2 跳过、Web 140/140，无失败。完整测试未调用真实付费模型，Vite 仅保留既有大 chunk 警告。

**边界**：CODEOWNERS、GitHub ruleset/必需检查仍需维护者在 GitHub 侧配置；本变更不修改这些远端设置，也不代表分支保护已经生效。`.github/workflows/ci.yml` 属高风险改动，合入前需要非作者真人审查当前 head。
