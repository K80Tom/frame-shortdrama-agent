# main 后端与短剧领域约定

- 开发前阅读[总体设计](docs/总体设计.md)与[技术架构](docs/技术架构.md)，按已确认需求工作；技术候选和待验证事项不能当作已确定选择，需求或数据结构变化时同步文档、样例、校验与测试。
- 本包独占 PostgreSQL、模型密钥、付费提交与媒体写入；跨包依赖与客户端边界遵循根目录 `AGENTS.md`，不向 `agent`、`web` 或 `cli` 泄露这些能力。
- 后端采用 NestJS＋Fastify：Controller 负责请求入口，Service 承担业务协调，后台调度随应用运行；拆解内核与数据契约保持可独立调用，不依赖 HTTP 请求对象。
- 保留原剧情和对白；允许补齐已获授权的制作细节。区分原文事实、用户要求与 AI 设计，保留原文引用、字段来源、制作计划版本及执行记录。
- 分镜一行一个连续镜头。普通修改与按场重做必须保护人工修改和其他场次，生成可比较的新候选；共享设定变更先展示影响范围，用户采用候选后更新并保留可恢复版本。
- 支持全自动与配置人工节点；有限返修仍不达标或预算不足时保存成果、报告未完成，人工处理并满足续跑条件后继续，不降低已确认质量底线来冒充完成。
- 局部任务阻断只暂停受影响任务及其依赖，独立任务在预算内继续；全局问题暂停全项目，存在阻断项时整集仍未完成。
- 无法确认的关键剧情事实集中交给用户澄清；已授权的制作细节可以自动补齐。人工回答后更新相关版本并重新检查，不以猜测剧情事实解除阻断。
- 资产目录是事实源，Milvus 只是可重建投影；资产元数据修改与向量重建必须显式执行。自进化 Evidence、Probe 与 Registry 事件保持不可变，候选经固定离线验证和人工采用后才影响新运行，历史运行继续使用冻结策略。
- 技术复核不等于视觉语义审核；3D 为 prompt-only；声音能力以实际供应商和本地检查结果为准，不把配置存在宣称为生成质量通过。
- 用户讨论方案时先完成解释；明确要求实现后，在已确定范围内一次交付一个可验证的小功能。未经运行验证，不把目录、样例或模拟输出称为已经实现的 Agent 能力。
- 交付时报告实际改动、验证结果和未验证部分；模型或提示词变化检查输出质量，保存与重做变化检查对应行为，命令必须实际存在且经过验证。
- 模型与具体费用在接入时核实；密钥只由服务端配置读取，不写进版本库、日志或浏览器。测试使用桩模型，未经明确授权不触发真实付费生成。
