# 独立短剧 Agent 项目约定

- 开发前阅读 [总体设计](docs/总体设计.md)，按其中已确认需求工作；技术候选和待验证事项不能当作已确定选择。需求变更时同步相关文档。
- 用户明确要求在本目录从零开发，不在同级旧平台上二次开发。
- 同级三个旧代码目录默认仅为参考资料；2026-09-27 用户明确授权复制其中 3D 导演台的白模功能到独立前端。复用代码需记录来源，新实现必须能脱离它们运行，不调用公司的 Main API 或依赖其数据库、账号、部署配置。
- 整体目标是自动完成真人拟真短剧生产，交付完整成片与网页可编辑项目。剧本拆解与制作计划是第一个开发里程碑，不代表整体产品仅包含文本拆解。
- 拆解结果使用结构化数据，分镜一行一个连续镜头；JSON 可用于保存和交换拆解结果，CSV 为可选导出。
- 第一里程碑的数据设计基线见 [数据结构 v0.1](docs/数据结构-v0.1.md)；原文引用、制作计划版本及执行记录遵循同一份结构，变更时同步样例。
- 保留原剧情和对白；允许补齐已获授权的制作细节，区分原文事实、用户要求与 AI 设计，保留原文引用与字段来源。
- 内核与界面分离。`web/` 的「真实项目」已接入本地事实拆解与候选分镜；其他剧本/分镜示例页和本地白模仍是演示或人工编辑，不等于媒体自动生成。
- 普通修改与按场重做保护人工修改和其他场次，生成可比较的新候选。共享设定变更先展示影响范围，用户采用候选后更新，保留可恢复版本。
- 独立资产库、生产质检、预算与运行状态属于产品范围；不因此引入旧平台的企业素材审批、积分、组织权限等业务模块。
- 支持全自动与配置人工节点；有限返修仍不达标或预算不足时保存成果、报告未完成，人工处理并满足续跑条件后继续，不降低已确认质量底线来冒充完成。
- 技术选型围绕独立内核做最小实现；不因旧仓存在多个 Agent、运行时或框架而照搬。
- 主工程已确定采用 TypeScript；具体框架及其确认状态以 [技术架构](docs/技术架构.md) 为准，推荐方案不能视为已选定或已授权实现。
- 后端已确定使用 NestJS＋Fastify：NestJS 组织 Controller、Service、Module 和依赖，Fastify 作为 HTTP 适配器。Controller 负责请求入口，Service 承担业务协调，后台调度随应用运行；拆解内核与数据契约保持可独立调用，不依赖 HTTP 请求对象。
- 局部任务阻断时只暂停受影响任务及其依赖，独立任务在预算内继续；全局问题暂停全项目，存在阻断项时整集仍未完成。
- 无法从上下文确认的关键剧情事实集中交给用户澄清；已授权的制作细节自动补齐。人工回答后更新相关版本并重新检查，不以猜测剧情事实解除阻断。
- 用户询问或讨论方案时完成解释；用户明确要求实现后，在已确定范围内推进。一次交付一个可验证的小功能。
- 未经运行验证，不把目录、样例、模拟输出称为已经实现的 Agent 能力。
- 交付时报告实际改动、验证结果和未验证部分；数据结构变化同步更新样例与校验，模型或提示词变化检查输出质量，保存与重做变化检查对应行为。
- 启动、检查和测试命令在实际建立并验证后补充，不编造命令。
- 模型与具体费用在接入时核实；密钥由服务端配置读取，不写进版本库或发送到浏览器。
