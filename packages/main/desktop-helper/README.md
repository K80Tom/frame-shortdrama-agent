# macOS 豆包桌面桥

这是本项目自行实现的窄用途 macOS Accessibility 桥，不是豆包官方 API、SDK 或命令行工具。它不使用 Codex 会话工具，也不读取豆包账号文件、Cookie、Token、内部数据库或私有网络接口。

构建（仅 macOS，需要 Xcode / Command Line Tools 的 Swift 编译器）：

```sh
node scripts/build-desktop-helper.mjs
```

产物保存在 Git 忽略的 `outputs/private/desktop-helper/OHAO Desktop Bridge.app`。构建使用本地临时签名；不安装开机启动，不修改系统权限，不启动生成。首次使用需由用户在「系统设置 → 隐私与安全性 → 辅助功能」通过加号选中这个 `.app` 并允许。开发版虽然 bundle ID 固定，但 ad-hoc 签名的指定要求依赖代码哈希；重新构建可能让旧授权失效，即使系统开关仍显示开启。此时需用户明确授权，在系统设置移除旧条目、重新添加完全同一个 `.app`；仅关闭再开启不一定刷新旧签名记录。构建脚本不会自动修改授权、安装证书或削弱签名验证。

## 协议与边界

后端通过 macOS LaunchServices（固定 `/usr/bin/open -n -g -W -a <本项目桥接app>`）启动已授权的 app，而不是从 Node 直接执行包内二进制。这样保持桌面权限归属于用户授权的 OHAO Desktop Bridge，不要求给 Node、Terminal 或 Codex 扩大权限。参数只有以下三种。JSON 通过 `outputs/private/desktop-bridge-ipc/` 下每次独立的 `0700` 临时目录与 `0600` stdin/stdout 文件传递，不把提示词放进命令行参数或日志；响应拒绝符号链接、硬链接和超过 16 KiB 的内容。

- `health`：只检查固定 app 安装信息与本进程 Accessibility 信任，不读取 UI、不弹系统权限请求。
- `diagnose`：仅供明确发起的本机只读排障，不加入健康轮询。只观察固定豆包进程的现有窗口，输出白名单角色、任务 URL 类别、输入框文本长度、是否恰为已观察固定占位提示、字符计数、可设置性、选择/可见字符范围及子节点 title/description/value 的类别和长度。任务 WebArea 内所有可写文本区都会报告，即使不符合最终输入框锚点。最多报告 10 个窗口、每窗 3 个文本区、每文本区 5 个子节点；不输出用户文本、窗口标题、完整 URL 或任务 ID，不打开 app、不切换焦点、不修改输入、不申请权限。
- `submit`：接收 `{jobId,prompt,outputPath}`。仅允许 `desktop_<32位小写十六进制>` 任务及固定 `outputs/private/desktop-assets/<jobId>/result.png` 路径结构。后端适配器进一步限定在当前项目根目录下。

健康检查合并并发请求并缓存最多 2 秒，未授权结果也会过期。正常 app 退出后只清理本次临时目录。启动或提交超时不是远程取消：适配器先返回状态不明确，继续用 `open -W` 观察 app 退出，期间保留输入文件并阻止新的原生启动，不自动重发。若观察额外 10 分钟仍未结束，仅停止 `open` 观察进程、保留该小型目录，并继续阻断当前后端实例的原生启动；须人工核对桥接 app 已退出与原任务状态后再恢复。不会把杀死 `open` 当作停止豆包任务，也不会自动清理可能仍被读取的文件。

提交只操作已安装 `/Applications/DoubaoWork.app` 中的 `com.work.pc.doubao` / `com.work.pc.doubao.browser`：要求唯一可核实的标准任务窗口（`AXWindow / AXStandardWindow`、固定豆包任务 URL、唯一任务输入框）；壳窗口、菜单、文件窗口不作为任务候选，不用标题或位置合并窗口，因此两个真实任务窗口仍会阻断。先保护未发送草稿，打开新任务，仅在实际核实的空白页 `chrome://doubaowork-chat/chat`（可带末尾 `/`）按可见 Accessibility 标签选择 Seedream 5.0 Pro，核对完整提示词后发送一次。多任务窗口、页面不确定或旧任务页都停止。

输入框定位不依赖其文字：仅在唯一已验证 task AXWebArea 内、具有精确“更多技能”工具锚点时，选择唯一 enabled 且 AXValue 可设置的 AXTextArea；搜索输入框、只读回答与多个可写文本区均不放行。空输入与占位提示严格区分：真实空 AXValue 可为空；AXValue 恰为实机观察到的 `发消息或创建任务... / 使用技能 @ 添加资料` 时还须 `AXNumberOfCharacters = 0` 才可视为空；字符计数缺失或矛盾则停止。其他非空文字一律保留为草稿，不因标签包含提示词而清空。输入先尝试设置 AXValue 并核对完整提示词；只有失败后仍核实为空才使用剪贴板粘贴兜底，部分或未知内容绝不叠加输入。粘贴临时使用并恢复系统剪贴板，若用户同时改变剪贴板则不覆盖用户的新内容。不会使用固定屏幕坐标；菜单控件不支持 AXPress 时仅使用刚读取的同名控件 bounds，失去目标焦点立即停止。

唯一的发送键之前以 `O_EXCL | O_NOFOLLOW` 创建并 `fsync` 任务目录中的 `submit-intent.json`。已有标记、提交边界超时或中断都不能自动重发。只有数字任务 URL、已清空输入框、非输入框文本中的完整已发送提示词三者同时成立才回报 `submitted`；文本被截断或其他证据不足时保留 `unknown`。结果只返回 `submitted / blocked / unknown` 与安全代码、可选的客户端任务引用；没有远程取消或退款承诺。

桌面桥只负责提交，不等待模型、下载任意链接、解析任意聊天文件路径或自己写入资产库。提示词要求豆包将结果保存到后端准备的固定任务文件，后端校验真实图片、入库及版本关联。`unknown` 仍只能等待同一输出或由用户核对，不作为一次新的生成许可。

## 验证边界

离线验证覆盖输出路径隔离、软链接拒绝、权限阻断、提交互斥、异常不重试、响应校验和发送前持久标记。Swift 构建与 `health` 不代表真实桌面生成已通过。真实端到端验收必须由本软件入口触发，并核对豆包选中模型、任务输出、保存引用和刷新后的持久结果。

目前仅 macOS、仅图片、固定已验证的中文客户端控件。客户端改版、权限缺失、登录/套餐限制、其他窗口抢占、休眠或保存失败会阻断；不自动购买权益、不切换为 API、不自动补发请求。没有 3D、Seedance、屏幕录像或通用电脑控制接口。
