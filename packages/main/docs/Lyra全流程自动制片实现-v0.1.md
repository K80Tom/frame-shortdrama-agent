# Lyra 全流程自动制片实现 v0.1

更新日期：2026-10-23

状态：已实现的本地整集生产总控；真实模型和媒体调用仍取决于本机连接配置与用户对本次运行的明确授权

## 1. 功能入口

前端入口是 `#/automation`。它把原来的单段文本生视频工具保留在 `#/automation/video`，同时新增面向一个已有项目和一个固定剧本版本的整集生产总控。

创建运行前，用户需要选择项目、剧本版本、画幅、目标时长、视觉风格、质量档位、自动化模式、制作流程（直出版 / 抽卡版）、3D 预演策略和预算上限。直出版每镜只生成 1 条视频、跳过 `candidates` 阶段（该阶段标记为 skipped），复核直接读取这条本地视频；抽卡版每镜生成 2–4 条候选后统一选优。提交按钮旁的授权勾选只适用于这一次运行；后端只接受 `allowPaid: true` 的严格创建请求。创建以后，表单输入、剧本版本、策略和预算不会随项目后续编辑静默变化。

总控页提供：

- 十阶段进度轨道；
- 镜头级任务矩阵；
- 问题收件箱和受影响范围；
- 候选抽卡、采用、整组重做和检查点确认；当前界面不提供逐个候选“驳回”按钮；
- 局部重试、整次暂停和继续；
- 运行历史、预算摘要、事件时间线和最终交付入口。

## 2. 十阶段执行链

固定整集骨架按以下顺序建立，分镜采用后再展开镜头级子图：

1. `prepare`：核对被冻结的项目、剧本版本、画幅、时长、策略、预算和付费授权。
2. `breakdown`：复用真实剧本事实拆解，运行确定性检查；全自动模式可用 `agent` 身份采用通过检查的版本，其余模式进入人工检查点。
3. `assets`：按人物、地点和道具的名称或别名精确匹配独立资产库；同优先级出现多个候选时明确报告歧义，不按创建时间猜选，也不把歧义当成缺失去重复生成。真正缺失的项目才展开为资产任务，在已配置生图连接时生成并安全导入本地资产库。镜头任务会再次确认其引用的资产唯一且可用。
4. `storyboard`：从当前已采用事实计划生成分镜候选，检查镜号、引用、对白覆盖和顺序；采用以后为每个镜头创建资产、可选 3D、视频任务和复核任务——抽卡版额外创建多个视频候选与选优任务，直出版只有 1 条视频且没有抽卡任务。
5. `director`：按策略决定是否建立白模。`never` 跳过，`always` 全部建立，`auto` 根据运镜、多人走位、长镜头、空间景别和动作关键词作确定性判断。白模的活动机位、位置、注视目标、焦距、运镜，以及人物站位、朝向和姿势会转成最长 1800 字的文字构图约束；这是 prompt 约束，不是把 3D 渲染图或原生相机控制参数传给供应商。视频产物元数据用 `directorConstraintMode="prompt-only"` 和 `directorSceneArtifactId` 保存这层关系。
6. `video`：按镜头与候选序号创建真实视频任务。每个任务读取镜头资产绑定，把去重后的资产 ID 按稳定顺序交给视频适配器；本地 PNG、JPEG、静态 WebP 由受控字节转成对应的 `data:image/...`，登记的远程图片使用 HTTPS 资源 URL，并在 prompt 中逐项说明“图片 N”对应的人物、场景或道具。资产缺失、绑定格式无效、同名歧义、超过 30 张或图片无法读取时，任务在调用模型前阻断。视频请求开启供应商原生音频，并为多个候选加入不同但不改变实体设定的创作方向。完成后先把 MP4 下载到本地媒体库，做哈希和 `ffprobe` 校验，再生成生产产物。
7. `candidates`：只接收已入库的本地 MP4。用画幅、分辨率和音轨等技术指标形成候选分数及推荐项；全自动模式采用推荐项，其他模式等待用户选择。
8. `review`：检查容器、哈希、画幅、时长和音轨。全自动模式在质量档位允许的次数内为失败镜头建立局部“视频 → 抽卡 → 复核”返修子图；返修视频 prompt 会带入上一轮真实失败项，并要求保留已确认人物、场景、道具和构图连续性。失败项会去重、限数和限长，不把整段内部记录无界传给模型；超限后等待人工处理。
9. `compose`：按已采用分镜的镜头顺序读取已选本地视频，用 FFmpeg 形成整集 MP4 和不可变时间线清单。
10. `deliver`：重新校验本地成片的哈希、容器、画幅、音轨和冻结目标时长。高质量、均衡、快速档分别允许目标时长的 12%、20%、30% 偏差，且至少允许 3 秒；超过容差会停在人工处理。只有校验通过的本地 MP4 才成为 `ready` 交付。

整集协调任务和镜头任务共用同一个持久化运行。任一节点没有执行器、配置、有效输入或本地产物时会产生明确问题并停止受影响依赖，不会构造成功结果或把供应商临时链接标成成片。

## 3. 自动化模式

| 模式 | 行为 |
| --- | --- |
| `auto` | 通过确定性检查的拆解与分镜由 Agent 采用；技术推荐候选自动选择；在质量档位限定内自动建立局部返修。 |
| `checkpoints` | 在拆解、资产、分镜和交付等关键阶段停下确认；视频候选需要明确选择。 |
| `coDirector` | 每个可见制作阶段都进入人工检查点，适合逐步导演控制。 |

所有模式都会在预算不足、关键剧情事实无法确认、外部任务状态不明、技术检查失败或重试上限用尽时等待人工处理。自动化模式不会降低已冻结的质量门，也不会用新提交掩盖一个结果未知的付费任务。

## 4. 持久化、幂等与恢复

迁移 `015_production_orchestration.sql` 建立 `production_runs` 和事务内 outbox；迁移 `016_agent_adoptions.sql` 允许全自动模式以 `agent` 记录通过检查后的计划/分镜采用。一个运行聚合完整保存任务、尝试、外部操作、产物、候选组、问题、质量检查、人工决定、时间线、交付、预算流水和事件。

- `clientRequestId` 唯一；相同标识和相同请求返回原运行，不同请求复用同一标识会拒绝。
- 聚合使用版本号作 compare-and-swap；并发写冲突要求重新读取，避免最后写入覆盖。
- 每次付费调用在执行前建立稳定的 `operationKey` 和预算预留；结果明确后结算或释放。
- 重启发现没有外部操作的本地执行被中断时，任务转为等待人工重试。
- 重启或暂停时若外部提交可能已发生，任务转入 `reconciling`/`unknown`，只允许查询原供应商任务，不自动创建第二次提交。已返回外部结果若连续遇到两次聚合 CAS 冲突，会持久化对账门禁、原任务 ID 和预算预留；带供应商任务 ID 的 unknown 视频连续 3 次仍无法确认时停止自动查询并转人工。
- 局部重试使受影响的下游产物、候选和交付失效，保留历史记录，再从最小依赖范围继续。
- 只有全部依赖任务完成、本地交付为 `ready`、有校验时间且整集检查通过，运行才会标记 `completed`。

生产事件与运行状态在同一数据库事务内写入，供界面轮询展示；当前没有独立消息队列消费者。

## 5. 本地媒体链

生产媒体保存在后端私有目录，以 MP4 内容的 SHA-256 作为 `media_<sha256>` 标识。生产聚合只保存 `/api/production-media/:id`、哈希和探测元数据，不向浏览器暴露绝对路径。

供应商视频下载有以下约束：

- 只接受 HTTPS；
- 解析并拒绝本地、私网和保留地址，连接固定到已校验的公网 IP；
- 不跟随重定向；
- 限制响应时间、大小和 `video/mp4` 类型；
- 保存前后校验 SHA-256、文件边界和 `ffprobe` 元数据；
- 读取时再次核对清单、哈希和探测结果；
- 不允许把远程 URL、符号链接或目录外文件作为合片输入。

FFmpeg 合片只接受本地媒体 ID，按分镜顺序缩放到统一尺寸并拼接为 H.264 MP4；所有输入都有音轨时才保留并编码 AAC 音轨。时间线清单记录有序输入、哈希、时长、尺寸、音轨状态和输出。媒体接口返回 `private, no-store`、`nosniff` 与沙箱 CSP；加 `?download=1` 可下载。

整集镜头视频请求固定 `generateAudio: true`，因此会请求视频供应商同时生成原生音频；抽卡、镜头技术复核和最终交付都会检查音轨是否存在。当前时间线直接保留候选视频中的音轨，没有另起配音、配乐、音效、混音、口型或字幕生产子图。

## 6. 预算与付费授权

生产表单要求用户明确勾选“本次运行允许调用已配置的付费模型”，并设置以微单位保存的预算上限。调度器在每个执行器运行前比较估算费用与剩余授权预算；预留将超出上限时，运行进入 `pausedBudget`，不会继续提交。

预算流水区分 `estimate`、`reserve`、`charge` 和 `release`。当前模型供应商接口没有返回统一可核验的实际账单，因此执行器使用本机配置的保守估算值做控制；它是运行内安全上限和审计记录，不等同于供应商最终账单。开启抽帧评估时，合成阶段按镜头把该视觉调用的记账上限写入同一条流水；余额不足则跳过这次评估，不另记一笔。

离线单元测试、构建和数据库测试都不提交真实付费任务。只有用户在生产创建表单对某次运行授权，且相应用途的模型连接可用时，运行才可能进入真实模型或媒体调用。

## 7. 已实现边界

本版本已经实现的是：

- PostgreSQL 持久化的项目级 DAG、任务状态机、CAS 更新、outbox、暂停、恢复、局部重试与预算门；
- 剧本事实拆解、确定性检查、人工或 Agent 采用；
- 资产名称/别名匹配、同优先级歧义阻断、缺失图片生成和本地资产导入；
- 分镜生成、检查、采用和镜头任务展开；
- 规则式 3D 白模快照，可供现有浏览器导演台读取；
- 绑定资产作为有序参考图片、白模转文字构图约束、多候选原生音频视频任务、供应商任务对账、安全本地入库和技术抽卡；
- 基于媒体元数据的镜头技术复核、有限局部返修；
- 本地 FFmpeg 时间线合片和交付复核；
- 与上述数据结构对应的生产总控 UI。

当前实现范围还不包含：

- 把人物长相、动作、剧情、台词和连续性判断登记成视觉语义模型检查结果；当前界面和数据明确称为“镜头技术复核”；
- AI 对 3D 白模画面进行视觉判断或自动精调；当前白模由明确规则生成，不是模型渲染结果；
- 独立配音、口型同步、音效、配乐、混音和字幕生成/烧录；当前使用视频供应商随镜头生成的原生音轨；
- 对供应商最终账单的自动回填；
- 面向生产环境的分布式调度、对象存储、CDN 或多用户权限。

因此，“技术检查通过”只表示本地文件、画幅、时长和音轨等程序条件通过，不表示镜头内容已经通过审美或剧情语义审核。真实全链路验收还必须在配置模型后，由用户明确授权一次试运行，并人工观看产物。

## 8. HTTP 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/production-runs` | 列出生产运行及汇总状态。 |
| `POST` | `/api/production-runs` | 用严格输入创建或幂等取得一个生产运行。 |
| `GET` | `/api/production-runs/:id` | 读取完整运行、阶段、镜头矩阵和问题收件箱。 |
| `POST` | `/api/production-runs/:id/actions` | 暂停、继续或明确重试一个任务。 |
| `POST` | `/api/production-runs/:id/reviews` | 确认检查点、选择候选或解决问题；协议保留任务级 reject 决定，但当前总控 UI 不提供逐个候选驳回按钮。 |
| `GET` | `/api/production-media/:id` | 读取已入库并重新校验的本地 MP4；`?download=1` 下载。 |

创建请求的关键约束：目标时长 15–900 秒，候选数 1–4，画幅为 `9:16` 或 `16:9`，模式为 `auto`、`checkpoints` 或 `coDirector`，3D 策略为 `auto`、`always` 或 `never`，`allowPaid` 必须为 `true`。

## 9. 本地运行和验证

应用数据库迁移并启动完整后端：

```sh
npm ci
npm run db:setup
npm run db:up
npm run db:migrate
npm run dev
```

另一个终端启动前端：

```sh
npm --prefix web ci
npm --prefix web run dev
```

打开 `http://127.0.0.1:5173/#/automation`。生产运行需要已应用 015–017 的 PostgreSQL（017 为事实提取账本的模型响应列；缺少它时不会启动付费事实提取或整集总控），以及拆解、生图、生视频等对应用途的本机模型连接。FFmpeg/ffprobe 不可用或媒体目录无法初始化时，合片和交付不会伪造成功。

不发起付费调用的验证命令：

```sh
npm test
npm run build
npm --prefix web test
npm --prefix web run build
```

概念背景和长期方向见 [Lyra 全流程自动制片构思](Lyra全流程自动制片构思-v0.1.md)。本文件只描述当前可由代码核对的实现与边界。
