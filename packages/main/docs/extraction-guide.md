# 剧本拆解 Agent：独立提炼指南

本指南用于“剧本拆解与制作计划”这个开发里程碑，记录从旧代码学习的方法和候选实现思路，不迁移旧公司业务平台。整体产品需求与当前决策见 [总体设计](总体设计.md)；本指南不替代完整生产系统的规格，也不表示技术选型已确定。

当前技术选择以[技术架构](技术架构.md)为准，第一里程碑的字段与保存规则以[数据结构 v0.1](数据结构-v0.1.md)为准。下文旧代码结构仅供学习。

## 2. 新内核的输入输出

输入建议分为两部分：

- 剧本：原文、原文版本、可定位的位置。
- 创作要求：已有的目标时长、表现风格、镜头设计约束，以及本次追问得到的答案。

输出建议包括：

- 剧情梗概。
- 场次及对应原文范围。
- 人物、场景与道具清单，使用稳定标识。
- 镜头：标识、所属场次、原文引用、画面动作、对白引用、景别、机位/运镜、预计时长、实体引用。
- 信息来源：原文事实、用户要求或 AI 设计建议。
- 校验问题与运行状态。

对白优先由程序根据原文引用还原，减少模型改写原对白的机会。多个镜头可以引用同一句对白；不能将合理的正反打误判成原文重复错误。

## 3. 一个协调器就可以起步

首个内核可评估以下固定步骤方案，是否需要自主工具循环仍需验证：

1. 程序整理原文与位置映射。
2. 模型提取梗概、场次和人物/道具。
3. 模型根据各场原文、已知实体与创作要求生成镜头。
4. 程序校验，必要时针对失败步骤进行有限修复。
5. 保存 JSON；如需要 CSV，从同一结果导出，避免维护两份不一致的数据。

“提取”和“分镜”可以是同一个模型执行的两个职责。先把每一步的输入输出写清楚，再依据实际问题决定是否增加自主工具调用或其他 Agent。

开发结构只需承担：输入整理、输出结构、提示词、模型接口、步骤协调、校验、保存与导出。角色/场次等是 Agent 的领域数据，不需要为它们先建设企业管理后台。

## 4. 用户已确认的能力如何保留

- 集中追问：收集上下文无法确认的关键剧情事实，已有答案不重复问；已授权的制作细节按已保存要求自动设计。局部问题只阻断受影响任务及其依赖，独立任务在预算内继续；相关规则已在技术架构 Q19–Q20 确认。
- 按场重做：复用该场原文和约束，生成一个新候选，比较后采用。
- 人工修改保护：保留原修订与人工改动；模型不能静默覆盖。
- 本地网页：调用同一个独立内核，展示原文、结果、问题和编辑操作。
- 单题材评测：只影响第一批评测样本，不限制内核的业务场景。

## 5. 验收从三件事开始

1. **忠于原文**：人物不串、场次与重要剧情不遗漏；对白能回源；镜头设计不增加剧情事实。
2. **修改能保留**：重做一场时其他场次不变，人工修改不被覆盖；中断后已完成结果仍可读。
3. **结果能使用**：JSON 结构正确，分镜一行一个连续镜头；如提供可选 CSV，其标识、内容与顺序应和 JSON 一致。

先用一份短样本跑通这三件事，再增加题材、长剧本、参考图与视频生成。模型价格与接口选择是可配置的实现决定，不是开始提炼拆解方法的前置条件。
