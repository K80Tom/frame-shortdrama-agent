# 单条视频自动化

本切片把用户输入的一段提示词和视频参数，持久化为一个异步 Seedance 任务，展示输入检查、模型确认、提交任务、视频生成、获取结果五个节点。它不改编小说、不执行剧本拆解、不生成多镜头时间线，也不把单条供应商视频当成已经完成质量检查的整集短剧。

## 运行条件与边界

- 显式执行项目现有的 `npm run db:migrate`，应用 `014_video_automation_runs.sql`，再重启后端。应用启动只检查迁移版本，不创建表。
- 在模型设置中完整配置并选中 **生视频** 连接。状态检查只检查本机配置，不请求供应商，不消耗模型额度。
- 每个新任务都须提交 `allowPaid: true`，并绑定页面确认的 `expectedModelConnectionRevision`。一次授权最多提交一次视频生成；金额预算、自动返修和质量评审尚未实现。
- 一个提示词生成一条 4–30 秒视频，支持 `9:16` / `16:9`、`720p` / `1080p`。这些是本机请求边界，供应商是否支持该组合由实际响应决定。音频开关只传递给供应商，不保证对白、口型、音画质量。
- 成果是经过 HTTPS 格式检查的供应商 URL，可能过期。后端不自动打开、下载或导入资产库；完成表示供应商成功返回有效链接，不等于本地视频持久交付或自动质检通过。

## HTTP 契约

所有接口仅允许现有本机客户端；POST 继续要求 `X-Shortdrama-Call: 1`，响应使用 `Cache-Control: no-store`。

| 请求 | 行为 |
| --- | --- |
| `GET /api/video-automation/status` | `{available,code,message,model,connectionRevision,busy,activeRunId}`；无迁移时 available 为 false。 |
| `GET /api/video-automation-runs` | `{runs}`，按创建时间倒序返回本机历史任务。 |
| `GET /api/video-automation-runs/:id` | 返回指定任务及真实节点状态。 |
| `POST /api/video-automation-runs` | 校验并保存 queued 后返回 HTTP 202；后台提交，不等待供应商完成。 |
| `POST /api/video-automation-runs/:id/reconcile` | 请求体必须为 `{}`；只查询已有供应商任务，不重新提交。 |

创建请求严格接受以下字段；不接受端点、密钥、模型名称覆盖、参考文件或其他隐式生成参数：

```json
{
  "prompt": "原创镜头：雨夜的灯塔，镜头缓缓推进。",
  "ratio": "9:16",
  "duration": 5,
  "resolution": "720p",
  "generateAudio": false,
  "clientRequestId": "a-new-stable-request-id",
  "expectedModelConnectionRevision": "current-video-connection-revision",
  "allowPaid": true
}
```

提示词为非空、最多 8000 个 UTF-16 代码单元；时长为 4–30 的整数。请求标识和连接版本只允许字母、数字、下划线与连字符，最多 100 字符。同一 `clientRequestId` 和相同规范化输入返回原任务；改动输入却复用标识返回 409。即使旧任务失败或结果不明，也不会因为重复请求而再次提交。

公开任务包含 `id/title/prompt/ratio/duration/resolution/generateAudio/clientRequestId/status/model/modelConnectionRevision/providerTaskId/result/error/errorNode/version/createdAt/updatedAt`，以及 `nodes: [{key,label,state,message}]` 与 `progress: {completed,total:5}`。成功时 `result` 为 `{videoUrl}`，其他状态为 null。节点 key 为 `input/model/submit/generate/deliver`，状态为 `pending/running/waitingExternal/succeeded/failed/needsAttention`。进度只数已完成节点，等待供应商时不推测生成百分比。

## 持久化与恢复

`video_automation_runs` 单表保存输入、模型与连接版本快照、任务状态、供应商 ID、结果、脱敏错误、版本和时间。`client_request_id` 唯一约束防止重复点击；部分唯一索引限制全局最多一个 queued / submitting / generating 任务。未知任务保留请求标识，但不占用新任务槽位。Memory 与 PostgreSQL 仓库都使用版本 CAS，输入及创建时间不可变；凭据、完整接口和原始供应商响应不进入任务记录。

后台在提交网络请求前先持久化 `submitting`。收到有效供应商 ID 后先保存，再解释状态与结果。成功结果进入 completed；供应商明确 failed / cancelled / expired 进入 failed。提交超时、网络失败、解析失败或重启时遗留 submitting 进入 unknown，不自动重发。已经保存供应商 ID 的任务只会查询该 ID；无 ID 的未知提交无法安全恢复，需要用户到供应商端核对。

Seedance 的创建接口可以只返回 `{id}`；客户端把这一有效确认映射为 queued，再通过查询接口获取状态。查询响应仍须有有效状态。协议依据为[火山方舟创建视频生成任务 API](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)，不假设创建响应已经带有视频结果。

当前进程保留提交时的客户端快照，运行中切换设置不影响已有任务查询。重启后如果原连接版本仍被选中，可以继续查询；如果连接版本已变化，任务转 unknown 并保留供应商 ID，不将旧 ID 发送到新连接。历史连接凭据恢复不在本切片范围内。

正常 generating 每 4 秒查询一次。一次查询无法确认结果时转 unknown，停止后台自动查询；显式对账仍只查询已保存的原任务。unknown 状态连续 3 次仍无法确认后，持久化 `reconciliationAttempts` 并返回 `VIDEO_RECONCILIATION_LIMIT_REACHED`，此后停止查询、保留原任务 ID，交由人工对账，绝不重新提交。未知任务查询后仍在生成时保持 unknown，避免与新活跃任务争用唯一槽位；成功或明确失败后可进入终态。进程内避免重叠轮询，跨 service 的 queued 提交通过数据库 CAS 竞争；本切片不提供多实例租约调度、取消供应商任务或自动重试。

## 验证

`npm test` 包含 `tests/video-automation.test.cjs` 的内存仓库、假适配器、注入 fetch 的客户端、本机 HTTP 与迁移静态检查；`npm run build` 检查后端 TypeScript。离线测试不读取 `.env`、不连接真实数据库、不调用真实模型。014 真实 PostgreSQL 迁移和供应商生成须另行在获得授权后验证。
