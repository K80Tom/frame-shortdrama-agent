# 小说校对 → 资产引用

本切片将已保存、已校对确认的人物、场景/地点、道具与素材登记关联。不改写小说，不生成剧本场次、分镜或 3D 内容。手工登记、校对和保存引用不调用模型；待补项只有在用户为本次候选单独确认额度后才调用设置中选定的生图连接。生成完成只进入候选，人工接受后才建立正式章节关联；拒绝的候选与生成溯源继续保留。

## 使用

1. 在项目目录显式执行 `npm run db:migrate`，应用 `009_novel_assets.sql`、`010_local_asset_media.sql`、`011_desktop_asset_jobs.sql`、`012_release_unknown_asset_slot.sql` 和 `013_asset_generation_candidates.sql` 后重启后端。服务启动不自动迁移；未应用 009 时原有小说校对仍可用，资产操作返回 503；只有 009 时仍能登记链接，本地图片导入提示补做 010，单图任务提示补做 012，候选决策与结构化溯源提示补做 013。
2. 打开 `#/assets` → 新建资产，登记 HTTPS 链接或选择「上传本地图片」，填写类型、名称、说明后保存。支持 PNG、JPEG、静态 WebP，最多 6 MiB、最长边 8192 像素、总像素 3200 万。目录为空时没有可选资产；旧示意图不进入真实目录。
3. 在 `#/novel` 对照原文完成条目校对，清除已解决的待确认说明，标记确认并先保存校对版本。
4. 选择该条目的同类型资产并保存引用；找不到合适素材时标记「待补」，可填写缺少什么。已确认但尚未选择资产的条目默认展示待补，不表示已完成一次人工决定。
5. 若条目已经确认并标记待补，先展开 `AssetVisualBrief`，核对已确认事实、精确原文依据、可设计变量、负面约束、置信度和待确认项。为本次候选单独勾选额度确认，点击「生成候选图片」；每个新的 `intentId` 只生成一张，可继续逐次授权生成多个候选。提交结果不明时不会自动重试。
6. 完整图片经格式、大小与哈希检查后进入 `awaitingReview`，不会自动修改本章引用。查看图片与安全溯源摘要后，点击「确认并关联」才追加本章新版本；点击「拒绝此候选」只记录决定，候选、媒体和溯源历史均保留。刷新后候选和决定仍可读取，历史章节版本只读。
7. 校对保存后仍选中刚才可见的条目，便于接续关联；仅在条目已删除或被筛选隐藏时回退到其他可见项。对白/引文不参与资产关联；跨章不会按同名自动绑定。

存在未保存校对、未确认条目、正在保存或正在查看历史时不能提交引用。引用选择和备注也有未保存提醒；切换条目、章节、版本、页面或刷新前不会静默丢弃草稿。

## 登记不等于素材质检

外部素材仍为 **HTTPS 链接登记**：服务端不抓取、探测或下载；前端不自动加载远程图片，点击链接才在外部打开。HTTPS 校验不代表链接可访问、长期有效、版权清晰或适合该人物。不要把密钥、私人凭据或短期敏感签名写入链接。

本地导入保存原始图片字节与 SHA-256 到 PostgreSQL，和资产登记在同一事务提交；刷新、后端重启后仍可预览和下载。服务端根据文件内容识别类型并检查容器结构、大小和像素上限，不信任扩展名，也不接受文件系统路径或远程下载地址。格式、大小与哈希检查只证明文件可安全保存，不是完整视觉解码或适用性质检；导入后需查看图片。人工接受只表示用户选择了这个候选，也不等于自动视觉质检、版权检查或角色一致性验收。图片内容和说明相同的重试返回原记录，不重复新增。

每条资产登记不可变，暂无编辑/删除接口。素材或说明变动时需登记新记录，再显式重选。引用保存目录记录的快照；本地导入保留原始图片，**远程链接不会固定文件内容**，远程内容可能变化或失效。生成素材的外观设计应写入素材说明，不写回原文事实。拒绝候选不会删除其媒体和溯源，也不会创建章节 linked 绑定。

## 状态与修改后的处理

| 状态 | 含义 |
| --- | --- |
| `linked` 已关联 | 人工为已确认条目选定同类型的已有登记；不表示媒体质检通过。 |
| `missing` 待补 | 人工明确暂未找到合适素材，asset 必须为空。 |
| `needsReview` 待重新核对 | 条目名称、描述、原文依据、类型或确认状态变化后，旧选择需再核对。保留原快照与备注，不自动沿用。 |

取消确认后再确认，不会自动恢复旧引用。修改无关条目不会使其他引用失效。删除条目或将实体改为对白会从新版本中移除该引用，旧历史不变。重新模型提取创建新条目，不自动搬用旧引用。

## 数据与接口

新增 `asset_catalog` 表，保存 `AssetRecord = { id, kind, name, description, resourceUrl, createdAt }`；kind 仅 character/location/prop。输入拒绝未知字段、不安全协议、URL 用户凭据与不合法值。目录只增不改；不导入示意数据。

`NovelContent` 增加可选 `assetBindings: { itemId, status, asset: AssetRecord | null, note }[]`，旧版本没有该字段也可读取。绑定只属于本章当前条目，不替换条目 ID、原文依据或来源。

`AssetVisualBrief` 固定使用 `schemaVersion: "asset-visual-brief/v1"`，保存 `itemId/kind/name/confirmedFacts/evidence/designVariables/negativeConstraints/confidence/pendingConfirmations`；每条 evidence 保存 `evidenceId/documentId/start/end/quote`。旧 `description/sourceQuotes/designNotes/promptPreview` 暂保留兼容，但不能替代结构化事实与依据。

迁移 013 新增 `asset_generation_candidates`，保存 `id/task_id/asset_id/chapter_id/item_id/status/version/review_note/accepted_revision_id/created_at/updated_at`。其中 `provenance_json` 保存 `promptVersion/promptSnapshot/model/modelConnectionRevision/inputRevisionId/sourceItem/brief/result`，result 只含 `sha256/mimeType/bytes` 等安全结果信息。迁移前在途任务没有可信提交快照时会明确标记 `legacy/unknown`，不会伪造精确提示词或来源。公开任务响应不返回完整提示词、内部 jobKey、条目内部快照或锁版本。

候选图片会出现在资产目录供预览，但 `awaitingReview`、`rejected`、`needsReview` 均不能通过普通资产引用接口直接绑定；服务端只允许候选审核里的明确接受动作建立首次关联。人工导入和普通登记资产不受此门禁影响。

接受前会先用 CAS 持久化包含基准版本、随机 nonce 和审核备注的内部接受凭据；服务重启会在 HTTP 开放前恢复该决定。只有基准版本本身或它的直接子版本已经关联同一条目与资产时，才能据此恢复为 `accepted`。更早历史里“曾经关联过”不能代替本次人工接受凭据，只会进入 `needsReview`；并发的不同接受意图不能覆盖既有凭据。

| 接口 | 行为 |
| --- | --- |
| `GET /api/assets` | 返回 `{ assets }`，按创建时间倒序、ID 正序。 |
| `GET /api/assets/:id` | 读取一条登记。 |
| `POST /api/assets` | 登记 `{ kind, name, description, resourceUrl }`，返回不可变记录。 |
| `POST /api/assets/import` | 导入 `{ kind, name, description, contentBase64 }`，返回相同结构的 `AssetRecord`；需要既有本机 POST 请求头。 |
| `GET /api/assets/:id/content` | 本地图片原始字节，按检测到的 MIME 返回，nosniff / sandbox / no-store；`?download=1` 下载。外部链接记录返回 404，不代抓取。 |
| `POST /api/novel-revisions/:id/asset-bindings` | 在当前最新章节版本上保存引用，返回新的 `NovelRevision`。 |
| `POST /api/novel-revisions/:id/asset-generation` | 使用新的 `intentId` 和本次显式额度授权，为一个已确认待补条目生成单张候选。 |
| `POST /api/asset-generation/:id/decision` | 提交 `{ decision: "accept" | "reject", expectedRevisionId, note? }`；接受后才追加章节关联。旧 `/api/desktop-assets/:id/decision` 路径兼容。 |

引用请求形状：

```json
{
  "expectedRevisionId": "当前章节版本ID",
  "bindings": [
    { "itemId": "本章已确认条目ID", "status": "linked", "assetId": "目录资产ID", "note": "选择理由" },
    { "itemId": "另一个已确认条目ID", "status": "missing", "assetId": null, "note": "缺少符合描述的素材" }
  ]
}
```

服务端只接受目录 ID，拒绝客户端伪造快照、重复条目、对白、跨章、未确认、不同类型、无变化和旧基准。章节指针在 PostgreSQL 行锁下再次校验；两次并发保存只能一次成功，另一请求返回 409，不覆盖历史。

本地图片的 `resourceUrl` 固定为 `/api/assets/<自身资产ID>/content`，只能通过导入接口创建；不接受客户端在链接登记接口伪造。迁移 010 的 `asset_media` 保存 `asset_id/mime_type/sha256/content`，目录和小说快照继续使用原有 `AssetRecord` 字段。备份数据库时会同时保存本地图片。

## 验证

```sh
npm test
npm --prefix web test
npm --prefix web run build
# 在已显式迁移 008、009 的专用测试库上配置 ASSET_TEST_DATABASE_URL：
npm run test:assets-db
```

数据库测试不自动读 `.env`，不自动建库/迁移，只清理自己创建的小说与资产记录。测试使用原创短文本和明确的测试链接，不下载媒体、不调用模型。

2026-10-22 本轮实际验收：后端 `npm test` 134 项、前端 39 项通过；前后端构建通过；在专用验收库显式应用 009 后，资产目录、小说引用、原有小说持久化共 3 项 PostgreSQL 测试通过。前端仍有既有 3D 分包体积警告，本轮未修改 3D。

浏览器用明确标注的原创灯塔文本与测试链接验证了登记、关联、待补说明、校对改动后待重核、重新选择、刷新持久化、历史只读、未确认禁用和未保存引用的切换提醒。该测试链接不提供真实素材，未用于正式小说；没有调用模型、访问素材链接或修改用户原有项目数据库。真实资产的可用性与适用性尚未验收。
