# 小说逐章拆解与校对

本切片只处理纯小说事实，不把小说改写成剧本。入口为工作台侧栏「小说逐章拆解」（`#/novel`），与旧的剧本 Run、事实采用、分镜和 3D 流程分开。

## 使用顺序

1. 显式执行 `npm run db:migrate`，应用 `008_novel_chapters.sql`，再重启本地后端；服务启动不会自行迁移。
2. 粘贴原文或导入 UTF-8 TXT，保留独立行的「第一章 …」「第二章 …」标题。出处链接仅记录来源，不会自动抓取。
3. 选择章节。可以免费建立引号待核对初稿；这只是引号定位，不是 AI 人物/场景/道具提取。
4. 要模型提取时，选择单次或多阶段模式，再明确勾选发送原文及额度确认。单次仅调用一次；多阶段包含提取、独立查漏、证据复核，发现问题最多再修复和复核一次（上限五次）。请求失败不自动重试、不回退其他模型。
5. 按人物、场景/地点、道具、对白/引文筛选，点击「定位原文」核对依据。可以修改名称与说明、补选依据、增删遗漏或错误条目、调整对白分类及所属人物。
6. 不能判断的条目保留待确认说明。确认前需清除未解决说明；对白和心理活动还需确定所属人物。保存可以保留待确认项，不会调用模型。
7. 「保存为新版本」追加本章校对版本，原文、旧版本和其他章不变。保存后保留当前条目选择；若它被当前筛选隐藏或已删除，则回退到可见条目。历史版本只读；旧页面保存冲突时保留草稿，可导出后人工核对，不能覆盖新版本。

模型重提取生成新的模型版本，不继承人工修改；已有人工版本仍保留在历史中，界面会再次提醒。多阶段模式保存各阶段检查点；后段失败或进程中断仍可读取前段保存的结果，不把 partial 当完成。未保存草稿只在当前页面内暂留，刷新或离开前有提示，不等于持久化。

## 多阶段检查与跨章实体表（2026-10-23）

- `mode: reviewed` 执行固定流程：首次提取→从原文独立扫描（不提供初稿）→程序合并有同一段落依据的同名同类型候选→模型证据复核→如有问题，局部补丁→修改范围及依赖对白复核。最多五次调用，每阶段无请求重试。
- 扫描必须返回每一输入段落恰好一行的实体映射，包括空清单；程序检查段落覆盖和映射ID。不把扫描覆盖率当成语义召回率。模型仍可能漏判。
- 细分类为 person/group/creature/place/object/material；程序由细分类推导原有 character/location/prop。出现方式为 present/mentioned/historical/imagined，不将“仅提及”塞入 uncertainty。对白新增 sound 音效。
- 局部补丁只允许修改复核问题指向的实体/对白，以及被改人物依赖的对白；新增实体需对应漏项问题段落。无关内容、原文和历史版本不能整章重写。复核未解决的条目保留问题说明，不自动确认。
- `GET /api/novels/:id/entities` 根据各章最新保存版本生成实体表（不是另一个易失内存库）。每项包含 canonicalEntityId、名称、别名、细分类，以及各章 item/revision/sourceRefs/confirmed。同名不自动合并；模型复用已有身份需从当前注册表选择同类型ID并接受证据复核。候选身份仍是模型判断，不是已确认事实。
- 模型上下文只读取前章当时的最新版本，不读取后章；分析记录固定 `contextRevisionIds`。前章改变后，旧分析保留原来的上下文快照，不自动改写后章或资产。旧记录没有新字段仍可读写；不会伪造旧记录的细分类。
- 细分类、出现方式、别名在正常校对页可修改并保存。人工改动后 analysis 标为 humanEdited，之前模型检查仅供追溯。跨章表来源于持久章节版本，重启后可重建，无需新增数据库迁移。
- `analysis` 保存阶段、各阶段安全用量、扫描映射和问题。请求级 attempt 保存累计 token（任一阶段未知时累计值保持 null），不保存供应商原始响应。中途校对造成版本竞争时停止后续提交，拒绝覆盖人工修改。
- 已知失败可显式传 `resumeRevisionId` 继续同章extract或extract+scan的完整、未人工修改检查点；上下文固定到原版本，条目ID不变，续跑账单只记新请求。unknown/submitted仍不可直接续跑。当前为API/评测命令入口，页面没有自动恢复按钮。
- 多阶段使用 `jsonOutput:true`，映射为 `response_format:{type:'json_object'}`；若网关拒绝不回退重试。协议外字段只投影丢弃，值、必填项、ID和引用仍校验。实测边界见[2026-10-23评测](小说拆解评测-2026-10-23.md)。

## 原文依据与待确认

- `rawText` 在导入后不可改写，保存 SHA-256；章节范围引用同一份原文。
- 位置使用整份原文的 **Unicode 码点**，零基、左闭右开 `[start, end)`。换行和 emoji 都计入；前端需要将 textarea 的 UTF-16 选区映射回码点。
- textarea 显示规范为 LF，保存原文仍保留 CRLF/CR；双向映射保证显示选区与原文一致。位于 CRLF 两字符内部的特殊边界不能精确显示时会提示，不会静默扩大引用。
- 每项至少一处原文依据，必须在当前章内，并满足 `quote === Array.from(rawText).slice(start, end).join('')`。修改引用时由原文重新切片，不接受编造引文。
- 模型只返回实体的段落 ID、引号候选 ID 与分类。服务端还原原文，不让模型重抄整段小说。对白第一处依据是正文，其余可记录归属上下文。
- 引号不等于发言：区分 `speech`（人物对白）、`thought`（心理活动）、`quotation`（引用/文字）、`sound`（音效）、`uncertain`（待确认）。复杂嵌套、身份不明等不能硬猜。
- 程序识别而模型遗漏的引号候选保留为待确认。没有引号的对白与非标准引号不保证完整覆盖，可人工补录。
- 所有模型项初始均为 `unreviewed`；「有原文位置」只证明可追溯，不证明实体概括、说话人归属或遗漏判断正确。

## 独立保存模型

| 记录 | 作用 |
|---|---|
| `novel_sources` | 不可变小说快照、摘要、出处 |
| `novel_chapters` | 章标题、整文范围、该章最新版本指针 |
| `novel_revisions` | 不可变内容版本、父版本、model/user/program 来源 |
| `novel_attempts` | 调用状态、开始/结束、错误码、安全用量摘要 |

保存请求携带 `expectedRevisionId`，在章节行锁下检查版本。模型执行期间仍可保存人工校对；迟到模型如果基准已变化，不能替换人工结果。原文与引用在保存和数据库回读时复验。

网络断开/超时标为 `unknown`，进程中断可能保持 `submitted`。这两种状态阻止同章再次付费提交，但允许人工校对；当前没有自动解锁或供应商核对恢复入口。失败后的手动再发起仍需明确确认。调用账本仅保存允许的 token 数字，不存密钥、思考正文或供应商原始响应。

## API

所有 POST 沿用本机安全边界和 `X-Shortdrama-Call: 1`。

| 方法与路径 | 用途 |
|---|---|
| `GET /api/novels` | 小说目录 |
| `POST /api/novels` | `{title, rawText, sourceUrl?}` 保存原文及章节 |
| `GET /api/novels/:id` | 原文与章列表 |
| `GET /api/novels/:id/entities` | 有来源版本的跨章实体表 |
| `GET /api/novel-chapters/:id/revisions` | 章内版本，从旧到新 |
| `POST /api/novel-chapters/:id/seed` | `{expectedRevisionId:null}` 免费初稿 |
| `POST /api/novel-chapters/:id/extract` | `{expectedRevisionId, allowPaid:true, mode?: single或reviewed}`；未指定仍为单次 |
| `POST /api/novel-revisions/:id/corrections` | `{expectedRevisionId, items}` 校对保存 |
| `GET /api/novel-chapters/:id/attempts` | 安全调用记录 |

小说输入最多 100 万码点 / 2000 章；当前单章模型输入上限 20000 码点，输出不超过 `min(8192, LLM_MAX_OUTPUT_TOKENS)`。超限不自动切章或提高额度。小说请求显式发送 `thinking:{type:'disabled'}`，旧的通用模型默认请求不变；参数被上游拒绝时不会去掉参数再请求。参考 [DeepSeek 思考模式协议](https://api-docs.deepseek.com/guides/thinking_mode/) 和 [火山方舟深度思考说明](https://docs.volcengine.com/docs/ark/deep-thinking?lang=en)，私有网关兼容性必须实测，不能只靠公开文档认定。
