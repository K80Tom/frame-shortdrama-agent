# P0.2：拆解持久化切片

更新日期：2026-10-01。

本文记录 P0.2 当时的 draft 保存边界。后续已新增事实 Candidate PlanRevision，见[P0.3 候选计划](候选计划-P0.3.md)；P0.2 本身仍不会创建候选或调用模型。

P0.2 把 P0.1 的无损原文索引接到独立后端的**最小可保存边界**。它不是正式拆解 Agent：不会调用模型、不会创建 `PlanRevision`、不会调度、不会自动采用候选，也不会记录或估算金额。

## 已实现的记录

| 记录 | P0.2 保存内容 | 不能据此宣称的能力 |
|---|---|---|
| `Project` | 标题、当前剧本版本指针、创建时间。 | 项目已经完成拆解。 |
| `ScriptVersion` | 原文、UTF-8 SHA-256、显示版本号、完整 `ScriptSourceIndex` JSON。 | 场次/人物/对白已被模型确认。索引里的候选标签仍是保守线索。 |
| `BreakdownRun` | 需求快照、已解析的模型选择、模型调用次数/输出上限、人工检查点、`draft` 状态。 | 已发出模型请求或已经花费费用。 |
| `extractFacts` Task | 固定输入清单、原文摘要、需求摘要、`pending` 状态。 | 任务已经执行、已通过校验或能自动续跑。 |

每个剧本版本通过项目行锁分配递增版本号；保存同一事务中构建并验证 SourceIndex，再更新 `Project.currentScriptVersionId`。Run 和其唯一的初始 Task 也同事务保存。P0.2 没有任何“启动 Run”的 HTTP 路径，因此创建 draft 不会触发真实模型调用。

## 数据库与迁移

- 驱动：`pg`；不引入 ORM。
- 数据库仅接受本机回环 `DATABASE_URL`（`127.0.0.1` 或 `::1`）；真实密码只放在已忽略的 `.env`。
- SQL 位于 `migrations/001_breakdown_p0.sql`；启动 HTTP 服务**不会**自动建表或迁移。
- 迁移命令使用事务迁移锁和 SHA-256 校验，已应用文件被修改会失败，而不是静默重跑。

项目提供 `compose.yaml`，使用 PostgreSQL 17、回环端口和独立命名数据卷。首次准备：

```sh
npm run db:setup
npm run db:up
npm run db:migrate
npm run test:db
```

`db:setup` 生成缺失的本地数据库配置，保留已有模型参数及数据库密码；`db:up` 等待容器健康。日常启动、停止、Navicat 连接和 Docker Hub 不可用时的镜像来源见[本地开发](本地开发.md)。配置或迁移就绪后应重启后端，启动时才会重新检查持久化依赖。

`test:db` 会检查 `001` 已应用，写入一个带随机 ID 的测试项目，并在结束时删除该测试项目。普通 `npm test` 使用内存测试适配器，因此不依赖 Docker/PostgreSQL；这不能代替真实 PostgreSQL 集成验证。

如果 `DATABASE_URL` 缺失，后端仍可提供既有模型目录接口，但 P0.2 持久化接口返回安全的 `503 PERSISTENCE_UNAVAILABLE`。如果数据库可连接但未迁移，则返回 `503 PERSISTENCE_MIGRATION_REQUIRED`。两个状态都不暴露连接串、SQL 或驱动原始错误。

## P0.2 本地 API

所有路径仍受现有本机保护：Host 必须为 `127.0.0.1`，不能带跨域 `Origin`；POST 还需 `X-Shortdrama-Call: 1`。

| 方法 | 路径 | 结果 |
|---|---|---|
| `POST` | `/api/projects` | 创建项目。请求：`{ "title": "…" }`。 |
| `POST` | `/api/projects/:projectId/script-versions` | 保存原文并构建无损索引。请求：`{ "rawText": "…" }`。响应只含索引计数，不把大段原文回显。 |
| `GET` | `/api/projects/:projectId/script-versions` | 读取该项目的剧本版本摘要。 |
| `POST` | `/api/projects/:projectId/breakdown-runs` | 创建 `draft` Run 和一个 `pending extractFacts` Task。 |
| `GET` | `/api/breakdown-runs/:runId` | 读取 Run、初始 Task 和冻结输入清单。 |

创建 Run 时必须给出正整数 `maxModelCalls`（1–8）和 `maxOutputTokens`（256–32768），即使本阶段不会调用模型。可选 `modelConfig` 只允许项目已配置模型与其合法推理档位；未提供时会快照当前默认配置。P0.2 固定为 `checkpoints` 模式，并始终保留 `candidatePlanReview`，以符合“Candidate PlanRevision 一律人工采用”的已确认规则。

`inputManifest` 当前固定登记：

1. 当前 `ScriptVersion` 的 `rawText` 与 `sourceIndex`，摘要为原文 `contentSha256`；
2. 本次 Run 的 requirements 快照，摘要为确定性 canonical JSON SHA-256。

P0.3 已补充手工输入的候选事实校验与保存；真正的 StageExecutor、Attempt/ModelCall 和模型输出转换仍未实现。不能将 P0.2 的 `extractFacts` Task 或 P0.3 的手工候选当成 Agent 已经自动提取过事实。

## 仍未实现（刻意保留）

- P0.2 本身不含 `PlanRevision`；P0.3 仅新增事实候选，仍无 Shot、Issue、Check、Adoption；
- 队列领取、lease、重试、恢复、Pi Agent Core；
- 模型调用登记、真实费用预留/结算；
- 模型生成后的结构校验、语义复核与一次修复；
- 网页接入、TXT 上传、媒体和对象存储。

这些边界避免“已经能保存一份 draft”被误解为“剧本拆解 Agent 已运行”。
