# 本地开发：Docker PostgreSQL

数据库由 Docker Compose 管理；NestJS 后端与 React 网页仍在本机 Node.js 中运行。

## 首次准备

打开 Docker Desktop。在项目根目录（包含 `compose.yaml` 的 `shortdrama-agent-lab/`）执行：

```sh
npm ci
npm run db:setup
npm run db:up
npm run db:migrate
npm run test:db
```

`db:setup` 为缺失项生成随机本地密码和 `DATABASE_URL`，保留已有模型配置；重复运行不会换密码。`.env` 仅当前用户可读写，并已被 Git 忽略。已有外部数据库连接时不会覆盖，配置不一致会报错。无需把密码写进代码或前端。

`db:up` 等待容器健康；`db:migrate` 显式执行 SQL 迁移，HTTP 后端不会自动建表。当前迁移还包含事实检查与采用记录、分镜尝试/候选/采用记录、项目来源链接字段（006）、人工校对版本（007）、小说章节与历史（008）、已有素材登记及本地图片（009–010）、图片生成任务与候选（011–013）、独立单段视频（014）、项目级生产运行与 outbox（015）、自动采用 actor 约束（016），以及事实提取账本中的模型响应列（017）。项目读写在 001–007 之后即可用；未应用 017 时付费事实提取和依赖它的整集生产总控不会启动，避免模型已经返回后账本写入失败。

升级已有数据库前先做本地备份，再执行迁移并重启后端。迁移整体使用事务，逐项核对已执行文件的校验和。校验和按 LF 字节计算。读取迁移时只把 CRLF 折成 LF，再计算校验和并执行，这样 Windows 检出或编辑器写成 CRLF 时仍与仓库里的 LF 哈希一致。除此之外不忽略 SQL 变更，也不做其他空白归一化。已核实的历史 003 比当前文件末尾多一个 LF；迁移器仅兼容该文件的两个固定哈希，不重写历史账本。若某台 Windows 机器曾在折叠换行之前把 CRLF 原文的哈希写入 `schema_migrations`，再次迁移会报校验和不匹配；对照当前 LF 哈希更新那几行记录，或在备份后使用新的本地库。

## 每次开发

```sh
npm run db:up
npm run dev
```

后端默认监听 `http://127.0.0.1:8788`。出现新 SQL 迁移时，在启动后端前先运行 `npm run db:migrate`。修改 `.env`、首次完成迁移或修改后端源码后，停止并重新执行 `npm run dev`，让后端重新构建并读取配置。

另开终端启动网页：

```sh
npm --prefix web ci
npm --prefix web run dev
```

网页默认在 `http://127.0.0.1:5173`。「真实项目」和「自动制作」通过本地 `/api` 代理接入 PostgreSQL、文字能力、资产库和媒体生产；旧的示例工作区仍使用 localStorage，手工白模使用 IndexedDB。项目级生产总控已实现持久任务、预算、恢复、参考图片镜头候选、供应商原生音频、技术复核和本地合片；真实付费模型输出质量仍需在用户明确授权的试运行中验收，页面不会把技术检查标成视觉语义审核。

常规网页的 `/api` 固定代理到 `127.0.0.1:8788`，后端 `npm start` / `npm run dev` 使用 `.env` 的 `DATABASE_URL`。验收时临时指定的其他端口/测试库不应替代常规入口；退出临时 Vite 进程，再按以上命令启动即可恢复正常连接。数据库迁移不会自动把验收小说或测试资产复制到常用库。

只读检查后端：

```sh
curl --fail http://127.0.0.1:8788/healthz
```

`healthz` 只表示 HTTP 服务已启动；数据库真实读写以 `npm run test:db` 和持久化 API 验证为准。文字接口与门禁见[首个里程碑实现](首个里程碑实现.md)，整集生产接口和边界见[全流程自动制片实现](OHAO全流程自动制片实现-v0.1.md)。

## 自动制作的本机依赖与使用

应用 015–017 后重启完整后端，再打开：

```text
http://127.0.0.1:5173/#/automation
```

创建整集运行前先在「模型设置」为需要的用途配置连接：剧本拆解/分镜使用文本连接，缺失资产使用生图连接，镜头使用生视频连接。镜头任务会读取资产库中的绑定图片作为 Seedance 参考；本地 PNG/JPEG/静态 WebP 由后端安全转成 data URL，登记外链使用 HTTPS URL，单镜头最多 30 张。未配置或不可读的能力会把对应节点标成需要处理，不会产生占位成果。运行表单要求明确勾选本次付费授权并填写预算；开发、构建和离线测试不会代替这次授权，也不会提交真实模型请求。

本地媒体库还需要系统能执行 `ffprobe` 和 `ffmpeg`。前者核对 MP4 容器、时长、尺寸、编码和音轨，后者按分镜顺序合片。缺少命令、媒体目录不可写、远程视频下载或校验失败时，受影响任务会阻断，远程 URL 不会被当作交付。生产媒体保存在 `outputs/private/production-media/`，该私有目录不能只靠数据库备份恢复。

最终交付还会比较合片时长与创建运行时冻结的目标时长：高质量、均衡、快速档的允许偏差分别为 12%、20%、30%，且至少 3 秒。该门槛是技术校验；页面不会将其显示成剧情、表演或视觉语义审核。

启动后可只读检查生产端点：

```sh
curl --fail http://127.0.0.1:8788/api/production-runs
```

不要用 `curl` 构造 `POST /api/production-runs` 作为普通健康检查：创建请求包含本次真实付费授权，配置齐全时后台会开始调度。页面允许暂停/继续、检查点确认、候选选择、问题解决和局部重试。重启前先让后端正常退出；即使意外退出，外部提交不明的任务也只对账原任务，不会自动重复发起。

## Navicat 连接

创建 PostgreSQL 连接，填写以下默认值；如修改过 `.env`，使用其中对应值：

| 字段 | 值 |
|---|---|
| 连接名称 | Shortdrama Local（自定义） |
| 主机 | `127.0.0.1` |
| 端口 | `5432`（`POSTGRES_PORT`） |
| 初始数据库 | `shortdrama_agent`（`POSTGRES_DB`） |
| 用户名 | `shortdrama`（`POSTGRES_USER`） |
| 密码 | 从本地 `.env` 的 `POSTGRES_PASSWORD` 复制，去掉包裹引号 |
| SSL / SSH | 本机开发不启用 |

本机账号是该开发实例的初始化管理账号。容器只发布到 `127.0.0.1`，不会对局域网开放 5432。

## 管理与保存

结束开发时，先在后端终端按 Ctrl+C，再停止数据库；重新启动时先 `db:up`，再启动后端。

```sh
npm run db:status  # 查看容器状态与端口
npm run db:logs    # 最近 100 行数据库日志
npm run db:psql    # 进入数据库命令行；用 \q 退出
npm run db:down    # 停止并移除本项目容器与网络，保留数据卷
npm run db:up      # 重建容器，继续读取原数据卷
```

数据卷为 `shortdrama-agent-lab_postgres_data`，PostgreSQL 17 数据目录挂载到 `/var/lib/postgresql/data`。停止容器、重启 Docker 或普通 `db:down` 不会删除数据；不要加 `-v` 或删除这个数据卷，除非明确要清空数据库。数据卷持久化不是备份。

数据库首次初始化后，单独修改 `.env` 的 `POSTGRES_PASSWORD` 不会修改库内密码；需要在数据库中修改密码并同步 `DATABASE_URL`。端口冲突时，在 `.env` 中同步调整 `POSTGRES_PORT` 与 `DATABASE_URL` 的端口，再运行 `db:up` 并重启后端。大版本升级不能直接替换镜像标签，需另做备份与迁移。

## Docker Hub 网络不可用时

Compose 默认使用 `postgres:17-alpine`。本机本次无法连接 Docker Hub，因此 `.env` 的 `POSTGRES_IMAGE` 使用了 Docker 官方镜像在 AWS ECR Public 的分发入口，并固定下载成功的 digest：

```text
public.ecr.aws/docker/library/postgres:17-alpine@sha256:b0f9560a2de083e2cc7382e75f808c7381a32852a7ec49117deedb300e552b24
```

这是下载容器镜像，数据库依然只在本机运行，不创建 AWS 数据库或云资源。其他机器可使用默认入口，或将 `POSTGRES_IMAGE` 设为 `public.ecr.aws/docker/library/postgres:17-alpine` 后拉取。来源：[Docker PostgreSQL 官方说明](https://hub.docker.com/_/postgres)、[AWS 关于 Docker 官方镜像分发的说明](https://aws.amazon.com/blogs/containers/docker-official-images-now-available-on-amazon-elastic-container-registry-public/)。

## 验证

```sh
npm test         # 编译 + 离线模型/原文/持久化契约测试
npm run test:db  # 真实 PostgreSQL 集成测试，只创建并清理自身的测试项目
npm --prefix web test
npm --prefix web run build
```

这些命令不调用真实模型或媒体生成；数据库、编排和媒体单元测试通过不代表真实模型质量、供应商恢复能力或实际人物/剧情内容已经人工验收。

Windows 上同一套 `npm test` 可以运行。私有文件仍以 `0600`、目录仍以 `0700` 创建；Windows 不保存 Unix 权限位，Node 通常报告 `0666`，因此权限断言只在 Unix 上强制。符号链接用例在无法创建链接时跳过（需要开发人员模式或提升权限，否则返回 EPERM），生产代码仍拒绝符号链接。`shortdrama-agent-lab/.gitattributes` 让 SQL 与源码按 LF 检出。
