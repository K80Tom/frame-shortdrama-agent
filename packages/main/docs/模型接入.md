## 配置与启动

需要 Node.js ≥ 22.19。先按[本地开发](本地开发.md)准备数据库与 `.env`；已有配置请原位修改，不要用示例覆盖数据库密码或其他设置。

在 `shortdrama-agent-lab/` 的本地 `.env` 中配置：

```dotenv
# 填写你获授权使用的 HTTPS 网关基础地址，不包含 /chat/completions
LLM_BASE_URL=
# 仅由服务端读取，不提交到仓库或放入 VITE_ 变量
LLM_API_KEY=
LLM_DEFAULT_MODEL=deepseek-v4.1-flash-1017
LLM_REASONING_EFFORT=model-default
LLM_MAX_OUTPUT_TOKENS=8192
LLM_TIMEOUT_MS=180000
LLM_MAX_CONCURRENT_CALLS=2
```

真实网关地址与密钥不写入本说明或 `.env.example`。若密钥已经出现在公开记录或不应共享的聊天中，应在服务方撤销并更换。

```sh
npm ci
npm run db:migrate
npm run dev
```

`dev` 先编译再启动，没有热重载。修改代码后重跑；仅改 `.env` 时重启后端。已有进程环境变量优先于 `.env`，如仍显示旧配置，需同时检查启动进程的环境。后端仅监听 `127.0.0.1:8788`，不需要本机模型代理。

没有配置 `LLM_BASE_URL` 或 `LLM_API_KEY` 时，后端仍可提供本地项目读取和实体校对；真实模型调用会被拒绝，不会退回旧服务或其他模型。历史 Run 的配置不改写，使用新模型需创建新的 Run；已有拆解候选仍可读取、校对、检查和采用。

### 配置含义

| 变量 | 默认值或要求 | 含义 |
| --- | --- | --- |
| `PORT` | `8788` | 本地 API 端口，仅回环地址监听。 |
| `LLM_BASE_URL` | 留空，配置时须为 HTTPS | 网关基础地址；服务端追加 `/chat/completions`。不接受带凭据、查询参数或片段的 URL。 |
| `LLM_API_KEY` | 留空 | 服务端通过 `api-key` 请求头发送，不使用浏览器保存或传入的密钥。 |
| `LLM_DEFAULT_MODEL` | `deepseek-v4.1-flash-1017` | 当前唯一模型，不能选择旧模型。 |
| `LLM_REASONING_EFFORT` | `model-default` | 使用服务端默认行为，不向上游发送 `reasoning_effort`。 |
| `LLM_MAX_OUTPUT_TOKENS` | `8192` | 本地一次输出预算，允许 256–32768；不是已验证的模型窗口或供应商输出上限。 |
| `LLM_TIMEOUT_MS` | `180000` | 等待上限，允许 1000–600000 毫秒；超时不代表上游取消或免费。 |
| `LLM_MAX_CONCURRENT_CALLS` | `2` | 同进程并发限制，超出立即拒绝，不排队或自动重试。 |

`.env` 被 Git 忽略；密钥不要写入日志、截图、示例、浏览器配置或提交记录。项目不会管理服务方额度，也不承诺新接口免费或不占用组织额度。

## 不消耗模型额度的检查

后端启动后运行：

```sh
curl http://127.0.0.1:8788/healthz
npm run models:list
```

这些命令只检查本地进程和配置目录，不向模型网关发请求。`GET /api/models` 只返回当前单一文本模型的信息；能列出模型不代表认证、额度、网络、上游响应格式或生成质量已经验证。

## 显式调用文本模型

以下操作可能消耗额度，只在接受调用成本时手动运行；每次执行仅发起一次模型请求：

```sh
npm run models:text -- "请用一句话解释什么是连续镜头" --allow-paid
```

本地 HTTP 示例：

```sh
curl http://127.0.0.1:8788/api/model-calls \
  -H 'Content-Type: application/json' \
  -H 'X-Shortdrama-Call: 1' \
  -d '{"model":"deepseek-v4.1-flash-1017","messages":[{"role":"user","content":"17+25等于多少？"}],"maxOutputTokens":4096,"allowPaid":true}'
```

- `POST /api/model-calls` 接收 `system/user/assistant` 文本消息；请求需显式提供 `allowPaid:true` 与本地调用请求头。
- 当前仅启用文本。图片理解、图片生成、视频、声音及其模型入口均不在此通道中；新模型窗口与视觉能力未验证，不沿用旧配置的能力数字。
- 适配器向网关发送 `stream:false`，读取完整的 Chat Completions 响应；一次真实请求已确认该模式与 `max_tokens:8192` 被接受，但生成内容未通过事实阶段输出协议。用户提供的流式请求样例不等于本项目已实现流式消费，其他额度与长期稳定性仍待验证。
- 不发送旧模型推理档位或 `reasoning_effort`，不自动换模型、回退旧接口或重试。
- 返回文本、请求/报告模型名、结束状态、用量及耗时；模型名不能独立证明底层权重身份，用量也不等于费用账单。
- `status:incomplete` 表示输出截断，不能当作完整成功；空输出报错，不自动追加额度续写。

独立适配器位于 `src/models/client.ts`，运行时契约位于 `src/models/contracts.ts`。直接脚本调用与本地 HTTP 使用同一校验和调用限制。单独文本调用不会创建生产 Run 或计划；网页的受控 Agent 阶段另行保存 Attempt/ModelCall 与候选。

## 失败与安全边界

缺少配置、旧模型名称或不支持的输入在本地拒绝。上游错误只返回脱敏信息，不反射原始响应、网关地址或凭据。遇到认证、权限、额度或限流错误，应核对授权与服务配置，不靠换身份绕过限制。

超时和响应丢失可能已经计费，人工重试前先核对。`allowPaid` 只是单次操作确认，不是金额预算、费用预留或自动退款机制。不会记录提示词、原始供应商响应、凭据或内部推理作为调试日志。

当前后端仅供本机使用，写请求需要 `X-Shortdrama-Call: 1`，网页来源限制为本地开发页面；没有远程用户认证，不应暴露公网、转发端口或直接部署至共享服务器。服务退出也不保证上游已经收到的请求被取消。
