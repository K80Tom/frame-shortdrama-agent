## 2. 根因归并

### A. 外部付费操作的"提交 → 对账 → 重提"闭环不完整（最大问题群，6 条运行共 89/118 条问题记录）

系统在防重复扣费上是保守且正确的：写 `submitting` 标记 → 提交 → 保存任务号。缺口有三层：

1. **提交结果没有分类**：`adapter.submit` 返回非 `submitted` 时一律落 `unknown`，即使供应商明确拒绝/连接未建立也无法区分"确定没发出去（可安全重提）"。
2. **对账没有兜底通道**：没有 `providerTaskId` 时 `reconcile` 直接记 `EXTERNAL_RECONCILIATION_REQUIRED` 并停止；轮次上限后也没有继续查询的入口。
3. **人工出口只有一半**：`abandonOperation` 能"确认未发生→释放预留→重提"，但**没有 `reconcileOperation`**（"确认已发生但查询失败→再查一次"），也没有批量处理，只能逐个调 API 或改 DB。

**开源对照**：可靠性领域把这类问题定义为 dual-write 问题，标准解法是三层幂等（checkpointing / workflow idempotency / business idempotency），并在**首次外部调用前**生成并持久化 operation key，任何重试都复用同一 key（OneUptime、Azure Scheduler-Agent-Supervisor、saga 补偿模式）。我们已有 operation key 与 `submitting` 标记（这一层是对的），缺的是"结果未知后的可操作闭环"。

### B. 运行终态不可修复

`terminal = {completed, partial, failed, cancelled}`，`partial` 被当作冷终态，任何 action 都被 `PRODUCTION_RUN_TERMINAL` 拒绝。实际后果：一个有失败任务的 run 想重试，只能直接改 `run_json`（本次排障中多次这么做，还踩了 `attemptCount = maxAttempts-1` 导致 `PRODUCTION_RETRY_LIMIT` 的坑）。

### C. 失败语义混用

`VIDEO_PROVIDER_FAILED` 同时承载"版权/内容审核拦截"与"供应商服务故障"。前者重提相同输入必然再次失败（每次仍计费），正确动作是改镜头包（泛化文案、移除人物/道具参考图）；后者才应该退避重试。开源视频工作流（ViMax）明确要求把 provider failure 与 content failure 分开处理，并对内容失败给出"简化动作/拆镜头"而不是重复提交。

### D. 可观测性不足

- 媒体进程失败时 stderr 被丢弃（`BoundedProcessRunner`），只能靠独立复现脚本重跑；
- `failInvalidOutcome` 只报"执行器输出未通过编排器校验"，不写真实原因（本次曾临时加 `console.error` 排查）；
- 后台只有一行启动日志，任务级失败原因要靠查 DB。

### E. 剪辑/交付契约不完整

- `cardVideoFilter` 缺 `[` → **自动剪辑从未成功过**（这是"前面都跑通了，剪辑这里咋回事"的直接原因）；
- 本机 ffmpeg 无 `drawtext` → 片头字幕必失败，无能力探测；
- 合成器没有目标时长契约 → 交付校验必然不匹配。

### F. 缺质量闭环

22 个镜头只有技术检查（容器/哈希/画幅/时长/音轨），没有画面语义评估。本次首轮抽帧评估就发现：动作方向拍反（设计"跑下楼梯"实拍"跑上楼梯"）、人物特征不一致、关键动作缺失、证件特写切双人跳变——这些问题**技术检查全过**。开源做法（CoAgent）是 Storyboard Planner → Synthesis → VLM Verifier → pacing-aware editor 的闭环，与我们补的方向一致。

### G. 文字阶段契约

拆解/分镜阶段的检查门禁本身工作正常（`PLAN_CHECK_FAILED`、`CANDIDATE_PLAN_INVALID`、`DIALOGUE_QUOTE_AMBIGUOUS` 都是正确拦截），问题是错误信息缺字段级定位，且没有低成本重跑（改提示词后重跑整个阶段）。

## 3. 本次已落地的改动

| # | 改动 | 文件 | 行为 |
| --- | --- | --- | --- |
| 1 | `partial` 运行可修复 | `src/production/service.ts` | `retryTask / reconcileOperation / abandonOperation / raiseBudget` 对 `partial` 放行；`pause` 等非修复动作仍拒绝 |
| 2 | 新增 `reconcileOperation` 动作 | `contracts.ts` / `service.ts` | 人工触发"对原外部任务再查一次"，不产生第二次付费提交 |
| 3 | `succeeded` 任务可 force 重跑 | `service.ts` | 下游输入变化（如目标时长调整）可重跑已完成任务；不带 `force` 报 `PRODUCTION_RETRY_REQUIRES_FORCE`；旧产物与下游自动作废 |
| 4 | 提交结果复用的精确判定 | `runtime.ts` | 只复用 `current` 产物，或"已知供应商结果但本地化失败"的 `superseded` 产物（`localizationErrorCode`）；已放弃操作的遗留产物不再触发付费决策 |
| 5 | 视频失败分类 | `runtime.ts` | 版权/内容拦截 → `VIDEO_CONTENT_BLOCKED`（不重试，明确"改输入"）；供应商故障 → 可重试并提示退避 |
| 6 | 未知操作给出可执行建议 | `runtime.ts` | 对账/放弃动作直接写进 issue 的 `recommendedActions` |
| 7 | 校验失败保留真实原因 | `service.ts` | `failInvalidOutcome` 写入脱敏后的字段级原因（屏蔽密钥/URL/控制字符），最长 300 字 |
| 8 | 抽帧评估接入生产合成 | `finalization.ts` / `main.ts` | compose 前按镜头评估 → `clipDirectives` + `frame-review` 产物；评估失败自动降级为普通合成，不阻塞成片；`OHAO_FRAME_ASSESSMENT=0` 可关闭 |
| 9 | 保留自动剪辑修复 | `production-media/composer.ts` | `cardVideoFilter` 缺失 `[` 已修；`drawtext` 能力探测与降级；`targetSeconds` 等比裁剪 |

## 5. 后续（尚未实施，已排序）

1. **提交意图先落盘 + 无任务号对账**：本地已有 Run 与 `clientRequestId`，可让 `reconcile` 在无 `providerTaskId` 时用同一请求指纹查询供应商；供应商不支持时保留人工通道。
2. **批量对账 UI**：`reconcileOperations` 已能一次查询同一 Run 中全部 `unknown` 外部操作，并在返回的运行里逐项给出任务与操作状态；没有供应商任务号的项保持人工对账，不会因此重新提交。运行详情页还没有对应的批量按钮（真实案例一次涉及 19 个任务）。
3. **版权拦截前置预检**：镜头包绑定了人物/道具参考图且文案含角色专名时，合成前提示风险（不阻断，只提示），减少纯损耗。
4. **评估成本入账（后续已接入）**：合成前按镜头预留并持久化评估结果，已获响应但供应商未返回金额时按每镜上限估算，详见[预算与付费授权](Lyra全流程自动制片实现-v0.1.md#6-预算与付费授权)。此处跑批的历史账本没有回填。
5. **按场重做**：参考 Toonflow / ArcReel 的事件图与"按场重做"能力，把失效范围从"任务"细化到"场次"。
6. **文字阶段字段级错误定位**：`PLAN_CHECK_FAILED` 类问题直接给出"哪一条事实、哪个字段"。
