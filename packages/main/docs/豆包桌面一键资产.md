# 豆包 API 资产候选生成与人工采用

更新：2026-10-23。该功能现在调用「工作台设置 → 模型连接」中选中的**生图 API**，不再操作桌面豆包、不需要 macOS 辅助功能权限。已从本机 `video_agent` 的现有私有配置显式导入豆包 Seedream 5.0/4.5 和 Seedance 2.5/2.0 四份连接；默认选中 Seedream 5.0 用于生图、Seedance 2.5 用于生视频。图片生成现在先保存为候选，只有人工接受后才建立正式章节关联。

密钥和私有网关地址只写入 Git 忽略的 `outputs/private/model-connections.json`，不写入源码、文档、浏览器或数据库任务。公开代码只保留中立协议适配。

## 如何使用

1. 在小说页将人物、场景或道具校对确认并保存，资产状态保持「待补」。
2. 展开 `AssetVisualBrief`，核对已确认事实、精确原文依据、可设计变量、负面约束、置信度和待确认项。
3. 为本次候选勾选一次额度授权，点击「生成候选图片」。请求携带新的稳定 `intentId`，并绑定当时可见的生图连接版本；其他页面切换了模型时，未调用上游就会要求刷新。
4. 后端按固定协议请求 1 张图，验证图片字节并保存候选媒体与结构化生成溯源。成果进入 `awaitingReview`，不会自动修改章节引用。
5. 可以为同一条目再次明确授权，逐张生成多个候选。对选中的候选点击「确认并关联」或「拒绝此候选」；接受后才保存新的章节关联版本，拒绝后候选、媒体和溯源仍保留。
6. 查看生成图。原文未说明的外观是视觉设计候选，不会写回小说事实。人工接受只是选择决定，不等于已经做过自动视觉质检、版权检查或角色一致性验收。

已有素材不会自动替换；对白条目不生成资产；未保存的校对或资产引用必须先处理。不自动重试或回退模型，不改编剧本，不连接、打开或修改 3D 导演台。

## 结构化视觉简报与生成溯源

`AssetVisualBrief` 固定使用 `schemaVersion: "asset-visual-brief/v1"`，字段为 `itemId/kind/name/confirmedFacts/evidence/designVariables/negativeConstraints/confidence/pendingConfirmations`。每条 evidence 保存 `evidenceId/documentId/start/end/quote`。已确认事实和原文依据由程序从当前小说版本整理，可设计变量不能反向写成小说事实。旧 `description/sourceQuotes/designNotes/promptPreview` 暂时保留兼容。

迁移 `013_asset_generation_candidates.sql` 新增 `asset_generation_candidates`，显式保存候选、人工决定及接受后的章节版本。`provenance_json` 保存 `promptVersion/promptSnapshot/model/modelConnectionRevision/inputRevisionId/sourceItem/brief/result`；result 记录 `sha256/mimeType/bytes`。完整接口、鉴权和密钥不进入候选记录、浏览器或仓库；公开任务只返回安全摘要，不返回完整提示词、内部 jobKey、条目内部快照或锁版本。

## 生图协议与成果

`DoubaoImageClient` 接受设置页保存的完整 HTTPS endpoint、模型 ID、`api-key`/Bearer 鉴权和超时；请求格式为 OpenAI-compatible/豆包图片生成协议，固定 `n:1`、禁止水印与流式输出。同时支持上游返回 `data[0].url` 或 `data[0].b64_json`。

- URL 成果只允许 HTTPS，下载时不转发供应商密钥，不跟随重定向。
- 图片最大 6 MiB，仅接受通过容器检查的 PNG、JPEG 或静态 WebP。
- 产物先写入私有任务目录，再使用不覆盖的原子发布方式交给导入器。
- 任务记录模型名与选择版本，不记密钥、完整接口或供应商原始响应。

## 状态与恢复

| 状态 | 行为 |
| --- | --- |
| 排队、提交、生成、导入 | 当前串行处理单张任务；网页关闭后后端继续。每次授权只对应一个 `intentId` 和一张候选。 |
| 提交前停止 | 配置、版本或本地目录在上游请求前被拦截；重试需要新的明确授权。 |
| 待核对 | 可能已计费但未能确认结果；不自动重发，相同条目仍绝不重提；可显式检查原结果，不再阻塞其他条目生成。 |
| `awaitingReview` | 图片已安全保存，等待人工决定；尚未建立章节关联。可以继续逐次授权生成其他候选。 |
| `accepted` | 用户接受候选，保存新章节关联版本；原文和校对条目不变。 |
| `rejected` | 用户拒绝候选；候选、媒体、备注和溯源均保留，可再次显式授权生成。 |
| `completed` | 只用于迁移前已经自动关联的旧任务读取兼容；新任务不再直接进入此状态。 |
| 已导回·需核对关联 | 生成期间章节已修改，保留图片但不覆盖新版本。 |

`011_desktop_asset_jobs.sql` 是早期桌面方案留下的表名，现在用于通用单图任务；`012_release_unknown_asset_slot.sql` 调整单活跃索引，同时保留 jobKey 唯一性；`013_asset_generation_candidates.sql` 保存多个候选、人工决定和结构化溯源。jobKey 由章节、完整条目快照和 `intentId` 共同形成：同一 intent 不会重复提交，新 intent 则代表用户新一次明确授权。这些名称不表示运行时仍会操作桌面。旧 `desktop-assets` HTTP 路径保留兼容；正常页面使用 `/api/asset-generation/*` 新路径。候选决定使用 `POST /api/asset-generation/:id/decision`，提交 `{ decision: "accept" | "reject", expectedRevisionId, note? }`。

## Seedance 生视频边界

`SeedanceVideoClient` 已支持完整任务集合 endpoint、多参考媒体 role、提交任务与按 task ID 查询，不自动重试，不暴露上游原始错误。生视频连接已可在设置中选择，但小说资产页只生成静态人物/场景/道具图；视频还没有绑定镜头生产 UI、持久轮询和成果入库，因此不宣称视频生产闭环已完成。

## 验证边界

离线测试覆盖图片 URL/Base64 响应、媒体限额与类型、鉴权分流、Seedance 提交/查询协议、错误脱敏、模型选择版本、本地产物安全、候选保存、接受/拒绝和关联冲突。本轮为避免未授权的真实计费，**没有发起真实生图或生视频请求**；配置完整不等于上游账号、额度和模型当前必然可用。离线结构测试也不能证明自动视觉质量，而本切片没有自动视觉质检。

早期 macOS 桌面桥代码仍保留作为可回滚的实验记录，主服务不再实例化它。
