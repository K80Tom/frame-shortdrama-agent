# 首个里程碑：剧本事实与候选分镜

> 历史切片说明：本页记录 2026-10-22 的剧本文字里程碑及当时的单模型状态。当前模型选择、小说拆解和媒体能力请以项目 README、[独立模型配置](独立模型配置.md)和后续专题文档为准。

状态：本地可运行的文字生产切片。项目读取与实体校对需要本地 PostgreSQL；执行生成时另需配置 MAAS 文本模型，并由用户在网页逐次确认可能计费的调用。当前只使用 `deepseek-v4.1-flash-1017`，不再使用旧 Codewiz 代理。原有代码与假模型/数据库集成测试记录见文末；一次真实非流式请求已成功返回，但事实候选输出协议校验失败，拆解尚未跑通，详见[实测记录](模型接入验证.md)。2026-10-30 增量：协议校验失败时返回脱敏的字段级诊断（路径＋原因，不含模型生成值），说话人证据不一致拆分为 `SPEAKER_EVIDENCE_MISSING` / `SPEAKER_EVIDENCE_ORPHANED` 独立错误码，拆解适配器与小说链路一致禁用上游思考；真实付费复测仍未执行，最新边界见[验证记录](模型接入验证.md)。

## 操作顺序

1. 运行 `npm run db:up`、`npm run db:migrate`、`npm run dev`；另开终端运行 `npm --prefix web run dev`。
2. 打开 [真实项目](http://127.0.0.1:5173/#/production)，创建项目并保存一集中文剧本。
3. 创建 draft Run。此时没有模型调用。按[模型接入](模型接入.md)配置服务端网关与密钥后，勾选付费确认并启动事实拆解；Pi Agent Core 执行单轮提取，从 MAAS 文本模型响应读取 JSON，原文证据别名还原并校验后保存为候选。缺少模型配置时拒绝生成，但不影响已有候选校对。
4. 在拆解校对清单查看人物、场景（地点）和道具的原文依据，修改已有实体的名称、别名、说明，保存为新候选。原文引用只读；此步骤不调用模型、不自动采用，旧版本保留。
5. 对所选候选运行程序检查。检查梗概、场次、人物、对白覆盖与重复、说话人、原文归属等；可识别的单行对白须完整引用正文，不能只提取其中几个字，也不能把人物名当作台词。阻断问题会列出原文引用；只有通过当前规则检查且仍为当前剧本最新版本的候选可以采用。新校对候选不能沿用旧检查。程序检查不能判断剧情语义是否准确，采用前需人工核对。
6. 采用事实后，勾选另一项付费确认，生成候选分镜。Pi Agent Core 对已采用的事实计划设计连续镜头。程序验证镜头按已采用场次的顺序排列、每场镜头连续编号、原文引用逐字一致、对白恰好覆盖一次且同镜头/跨镜头的对白顺序正确。景别、运镜、时长与画面描述全部标为 `designSuggestion`。人工核对后采用分镜。

所有采用使用项目当前指针的版本比较。保存新剧本版本会清除当前事实与分镜指针；采用另一版事实会清除当前分镜指针。历史候选和尝试记录保留。

模型切换不改写历史 Run 的模型快照或既有成果。使用新配置需创建新 Run；旧候选仍可查看、校对、检查和采用，不会自动重跑，也不会回退调用旧服务。

### 实体校对：保存新版本，不改写原文

- 三类实体均可查看实体及字段的原文引用；编辑只涉及 `name`、`aliases`、`description`。场景在这里指地点实体，不是场次安排。
- 新候选保留实体、场次、对白的稳定 ID，以及原文引用、制作要求和其他未修改内容。`parentRevisionId` 指向校对基准，`createdBy=user`、`reason=manualEdit`、`attemptId=null`；修改的文本为 `origin=user`，字段修改写入 `manualLocks`。
- 只有当前剧本的最新候选可编辑、采用；同一基准被另一页面先保存、剧本被替换或已采用指针变化时，返回冲突，要求刷新核对。历史候选只读，本轮不提供恢复旧版入口。
- 保存与采用分开：保存不改变活动事实或分镜，也不复用旧检查；新候选通过当前程序检查后仍需单独采用。
- `manualLocks` 当前记录校对字段及引入版本，同一校对链保留未被再次修改字段的记录；尚未实现按场重做、跨新 Run 自动继承或合并人工修改。重新提取会创建独立候选和新实体 ID，必须重新核对后自行决定是否采用。
- 已有数据库需显式运行 `npm run db:migrate` 应用 `007_entity_edit_revisions.sql` 并重启服务。迁移保留历史快照；内部 `revision_order` 确定保存顺序，旧记录按原有 `created_at/id` 顺序回填，不靠随机 ID 判断新旧。

### 白话理解：先保证“没漏字、没乱序”

- `林晚：你终于来了。🙂` 的正文是 `你终于来了。🙂`；只提取 `你`、漏掉句尾，或把 `林晚：` 一并当作台词，均不通过。
- 支持中英文冒号、人物名后的括号表演提示和空白分隔的人物列；偏移仍按 Unicode 码点计算，保留原文及 CRLF。
- **尚未解决的边界：** 正文内部出现括号说明时，返回 `DIALOGUE_BOUNDARY_UNCERTAIN` 阻断项，不猜测动作与台词的边界。多行续对白、小说式叙述等不在本轮完整性保证内。实体校对不能修改对白、说话人或原文引用，也不等于剧情澄清入口；人工核对本身不能绕过这些阻断。
- 事实检查升级为 `extract-facts-completeness/2`。旧 `/1` 记录仍可查看，但再次采用事实需重新运行程序检查。分镜校验升级为 `storyboard-validator/2`，旧分镜可读取，采用时按现规则重检且保留镜头 ID。
- **历史已采用结果不自动改写或撤销。** 既有活动事实仍可进入分镜生成；若此前已采用过旧检查结果，应主动重检事实后再继续，不能把升级视为已对历史项目补验。

## 接口与数据

- `POST /api/projects`、`POST /api/projects/:id/script-versions`：本地保存项目与剧本版本。
- `GET /api/projects/:id/plan-revisions`：按保存顺序返回项目全部事实候选，包括旧剧本的只读历史。
- `POST /api/plan-revisions/:id/entity-edits`：请求含 `expectedActivePlanRevisionId` 和 `edits`；每项为 `{kind, entityId, name, aliases, description}`，`kind` 取 `character/location/prop`。返回新候选，不调用模型。参见[静态请求样例](../examples/entity-edits-request.json)：实体 ID 必须替换为基准候选中的实际 ID，已采用指针填写页面所见值，尚未采用时为 `null`。
- `POST /api/projects/:id/breakdown-runs`：仅创建 draft。
- `POST /api/breakdown-runs/:id/execute`：请求体必须为 `{"allowPaid":true}`；单次运行，无自动重试，保存 Attempt/ModelCall 与候选计划。
- `POST /api/plan-revisions/:id/checks`：纯程序检查，不调用模型；`GET /api/plan-revisions/:id/checks/:checkId/issues` 查看问题。
- `POST /api/projects/:id/adoptions`：须提供 `planRevisionId`、`checkId`、`expectedActivePlanRevisionId`。
- `POST /api/projects/:id/storyboards`：请求体必须为 `{"allowPaid":true}`；依据已采用事实设计候选分镜，记录尝试与模型用量。
- `POST /api/projects/:id/storyboards/:revisionId/adoptions`：须提供 `expectedActiveStoryboardRevisionId`。

本地网页通过 Vite 代理访问后端；后端仍只监听 `127.0.0.1`，写请求要求 `X-Shortdrama-Call: 1`，仅接受本地开发网页的 Origin。浏览器不保存模型凭据。

## 范围与后续

本切片仅实现已有实体的名称、别名和说明校对；不新增、删除或合并实体，不编辑原文引用、场次、对白、说话人、梗概或真实候选分镜。按场重做、集中追问剧情歧义、自动修复模型坏输出、跨进程恢复运行尚未实现，也没有资产上传/引用、独立资产库、白模自动摆场、生图、配音、视频、剪辑或成片。`storyboard_revisions` 是独立的候选分镜版本，未合并进旧样例的 `PlanRevision.scenes[].shots`。这些能力需要在真实样例验收后继续设计，不应把当前流程称为全自动短剧生产。

### 接下来优先做前半段（2026-10-22）

3D 导演台暂不扩展，按小功能逐步推进：

1. **已落地的校对小步：** 人物、场景（地点）、道具展示原文依据，已有实体可修改名称、别名、说明并保存新候选，重新检查后采用；不直接覆盖已采用版本。实体增删合并及其他事实字段仍待完善。
2. **项目内参考图引用：** 先支持人工上传/选择人物、场景、道具参考图，不接自动生图或复杂全局资产库。绑定需明确属于哪版拆解、哪个实体，以及哪个素材版本；不能靠同名自动套用。缺图显示“未绑定”，不伪装为生成成功。
3. **镜头使用哪些资产：** 后续明确镜头可见的人物/地点/道具，再引用对应素材。说话人可能在画外，不把说话人或整场人物自动当作镜头出镜人物。

以上资产步骤尚未实现。当前 `assetRequirements` 仍为空；新一版事实提取会创建新实体 ID，旧版绑定不能未经核对直接迁移。上传的存储方式与限制在实施该功能时确定。
