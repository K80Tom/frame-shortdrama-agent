# AI 底座合同:统一 AI 网关(v0.2.0,#28,2026-07-23 冻结)

背景:AI 底座三层总纲(版本计划 2026-07-23,DC 拍板)——网关层(0.2.0)/
Agent 层(0.3.0)/Skill 层(0.3.x),治"AI 能力散且 mock"的根。本合同冻结
**网关层**的接口形状与纪律;首件工作包=Sol 下包 1(goal 全文
docs/goals/2026-07-23-v020-ai-gateway.md,其成功门禁与本合同互为验收锚)。

## 一、网关纪律(铁律,新功能一律适用)

1. **所有前端 AI 触点只许走 `/api/v1/ai/*`**,禁止前端直连 provider、禁止
   前端拼提示词(台账条 30 防复刻纪律同源;现状最大暴露点 ir-compiler.ts
   前端组装,0.3.0 EDIT 实现时后移,本合同先立规矩)。
2. **每笔真实 LLM 调用落一条 ai_calls**,无日志的调用视为事故。
3. **禁 mock**:接不了真就如实返回空态/错误,不许假数据装可用(DC 拍板
   "去虚假 mock");存量直连(Excel/视觉/Pi 等)按 S9 真假清单逐个迁入,
   迁完前在清单挂账,不误报完成。
4. 模板与组装规则(分层模板/grill 问题集/默认负面词表)只存服务端;
   **产出的草稿本身给用户可见可编辑**(草稿是产品,配方不是)。

## 二、接口形状(0.2.0 首批两触点)

- `POST /api/v1/ai/prompt-draft`:输入=文字描述+已选资产上下文;输出=
  **五层结构化草稿**(台账条 31 定序):画面元素层(实体参考)→光照层→
  色彩 palette 层→摄影质感层→负面约束层。五层齐全是门禁,层内容可空但
  层位不可缺——0.3.0 风格参考四件套(色卡/光影/摄影/负面集)将按层对位
  注入,接口形状现在就按此留位。

  **输入单位约束(DC 走查条 6,2026-07-24 补)**:草稿的输入单位=
  **单个分镜的生产意图**,不是整场/整集的成段描述。一段covering多个
  分镜、多张画面的散文直接生成一张草稿,产出的是"平均值",丢镜头间
  信息,且草稿与产物失去一一对应(确认卡和参考控制包都以单产物为
  锚)。所以:
  1. 服务端对输入做体检——检出多画面特征(明显的场景/镜头切换叙述、
     超长成段文本)时**不硬生成**,返回结构化引导:建议走剧本导入/
     拆分镜(#24 剧本 IR 链),拆完逐分镜生成草稿;判定规则服务端可调,
     宁可放行边界样本,不误拦单镜头长描述;
  2. 前端入口文案写清"描述这一个镜头要什么",粘贴长文时给"这像是
     一整场戏→去拆分镜"的分流入口,不静默截断;
  3. 原理口径(平台立场):平台的价值是**降低人对 context 的管控负担**
     ——把"一段散文"变成"逐镜头可控的结构化输入"正是干这个的,
     不是让 AI 在模糊输入上赌一把。
- `POST /api/v1/ai/asset-match`:先走既有受权限约束的语义/结构化召回做
  候选白名单,LLM 只做**白名单内重排+一句话理由**;不发明候选、不返回
  已删除或无权限资产;embedding/Milvus 故障沿既有 PostgreSQL 降级路径;
  空库如实空态。**已匹配结果=草稿候选,不自动进控制包**(台账条 38 语义
  铁律:工作台就绪引用是参考控制包唯一来源)。
- 通用:登录必需;网关环境开关关闭→503;按用户按 UTC 日限额超限→429
  人话错误;错误不透出 provider 原始响应。

### 2026-07-30 感知优先扩展：提示词优化、翻译与模型档位

这一节是对首批接口的兼容扩展。旧请求不传新增字段时仍可使用；旧响应里的
五层 `draft` 保持不变，只增加可直接显示和编辑的字段。

1. `GET /api/v1/ai/prompt-models`

   - 登录可读；
   - 只返回稳定产品档位 `quality`、`fast`，包含中文显示名、用途说明、
     `available` 与 `is_default`；
   - 不返回供应商模型 ID、环境变量名或密钥状态；
   - `available=false` 的档位不可提交。前端不得把同一个模型伪装成两档。

2. `POST /api/v1/ai/prompt-draft`

   新增可选输入：

   ```json
   {
     "model_key": "quality",
     "supplement": "用户自己保留的补充要求",
     "creative_context": {
       "visual_style": "写实电影感",
       "camera_direction": "中近景、低机位、50mm 焦段感",
       "reference_notes": ["保持角色造型一致"]
     }
   }
   ```

   `selected_assets` 仍只收资产 ID，名称、类型、描述与用途必须由服务端从
   PostgreSQL 重建，不信任客户端描述。

   **`media_kind` 必填（2026-08-18 补）**：`"image" | "video"`，声明本次草稿
   的目标媒介。服务端按它注入对应媒介的项目默认风格与生成模板
   （image=图片风格+图片模板，video=视频风格+视频模板），并决定成文文案
   （生图/生视频）。旧调用方必须补传该字段——缺失会 400，不再按图片兜底。

   输出：
   ```json
   {
     "draft": {
       "visual_elements": "...",
       "lighting": "...",
       "color": "...",
       "cinematic_texture": "...",
       "negative_constraints": "..."
     },
     "auto_prompt": "按五层拼好的系统自动段",
     "supplement": "原样保留的用户补充段",
     "prompt_text": "自动段与补充段的完整可用文本",
     "model_key": "quality"
   }
   ```

   五层内容必须达到可直接用于单个分镜生图的详细程度：角色、场景、道具、
   画风、构图、镜头、光照、色彩与参考资产作用均说明清楚。系统自动段和
   用户补充段分开返回，后者不得被覆盖。

3. `POST /api/v1/ai/prompt-translate`

   ```json
   {
     "prompt": {
       "auto": "系统自动段",
       "supplement": "用户补充段"
     },
     "target_language": "en",
     "model_key": "fast",
     "context": {
       "project_id": "uuid",
       "related_object_type": "shot",
       "related_object_id": "uuid"
     }
   }
   ```

   返回 `translation.auto`、`translation.supplement`、合并后的
   `prompt_text` 和实际使用的稳定 `model_key`。翻译保持段落、`@资产名`、
   数字、比例、型号和影视术语，不扩写或改变创作意图。每次调用以
   `prompt_translate` 用途进入 `ai_calls`。

4. 模型与错误纪律

   - 客户端只传 `model_key`，不得传任意模型 ID；
   - `quality` 与 `fast` 由服务端配置映射，未配置档位在供应商调用及审计
     预留前返回 `422 ai_model_unavailable`；
   - 供应商名、HTTP 状态、英文错误、内部状态不得进入用户响应。统一返回
     `ai_service_unavailable` 与中文业务说明；原始故障只留服务端日志和
     `ai_calls.error_code`；
   - 两个接口都只产出可编辑草稿，不创建生成任务、不自动扣费。

### 2026-08-05 公司 COL 文字通道扩展（#96）

1. 文字类 AI 走公司账户的 OpenAI-compatible COL 网关或火山方舟，按模型判定；
   Ark 生图、生视频和生音频链保持原样，不受本扩展影响。
   **优先级更正（2026-08-10 夜，产品负责人指挥文件第二节）**：本条原写「优先使用
   公司账户的 COL 网关」，现作废。文字通道与图片侧同一条判定顺序——火山方舟登记了
   的模型走火山，COL 只承接火山没有的模型。公司通道不关闭，只是排在火山之后；
   两条通道各自可缺席，只配火山、只配 COL、两条都配都是合法部署。
   能力默认模型同此优先级：火山在场时，拆解、提示词起草、翻译的默认模型取自
   `ARK_LLM_MODEL` / `AI_PROMPT_LLM_QUALITY_MODEL` / `AI_PROMPT_LLM_FAST_MODEL`；
   火山缺席时才由 `COL_SCRIPT_BREAKDOWN_MODEL` / `COL_PROMPT_DRAFT_MODEL` /
   `COL_PROMPT_TRANSLATE_MODEL` 接管。
2. `COL_BASE_URL` 与 `COL_APIKEY` 只从本地忽略环境或 KMS 内存注入，二者必须
   成对存在，不进入 ConfigMap、清单、日志、错误响应或审计正文。
3. `COL_TEXT_MODELS` 是从网关 `/v1/models` 核验后的精确模型 allowlist；
   `COL_SCRIPT_BREAKDOWN_MODEL`、`COL_PROMPT_DRAFT_MODEL`、
   `COL_PROMPT_TRANSLATE_MODEL` 分别绑定拆解、提示词起草和翻译，且必须属于
   allowlist。换模型只改部署配置，不改业务代码。
4. COL 任一配置已开始启用时，六项缺一即启动失败并点名缺失键；运行时模型只按
   精确绑定路由，客户端仍不得提交供应商模型 ID。
5. 每笔调用仍先写 `ai_calls` 预留，`provider=col`，保存实际响应模型、token、
   耗时和状态；不保存提示词原文、完整响应或凭据。

## 三、ai_calls 记账形状与 #22 对齐

- 必记:用途(purpose)、模型、输入/输出 token、耗时、调用者 user_id、
  关联对象、状态/错误码;**不存提示词原文与完整输出**(隐私+防复刻)。
- 归属:user_id NOT NULL;project_id 有项目上下文的触点必填(与运营底座
  合同 operations-foundation.md 第二节归属护栏一致)。
- 计价:**token 必记,积分可空**——LLM 未定价前 charged_points 为空并标
  `unpriced`,不伪造换算(Sol goal 边界照单);入 #22 `cost_entries` 视图
  时 unpriced 按 0 聚合并单列"未计价笔数",价格档定档后回填口径再补一次
  迁移。LLM 计价走能力档模式(参照 v0.3.0 能力档合同),不散配。

## 四、演进锚(不在 0.2.0 实现,形状先约束)

- **自定义 provider(0.3.0)= 网关的管理端**:provider 表+格式适配器
  (预置 Ark/OpenAI 兼容/Gemini)+key 进服务端密管;入口只在管理员面
  (丽芬 32-9,费用走平台积分红线)。网关内部实现需留 provider 抽象缝,
  但 0.2.0 只做 Ark 豆包一个实现,不预建配置面。
- **Agent 层(0.3.0)**:拆书定妆/提示词草稿/资产匹配升任务型 agent,
  可调平台工具,产物走确认卡不自动扣钱——网关是其唯一 LLM 出口。
